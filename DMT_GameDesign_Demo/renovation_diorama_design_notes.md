## 1. หลักการใหญ่: ทุกอาคารใช้ระบบเดียวกัน — "ไดโอราม่าในโมดัล"

**สรุป 1 ประโยค:** เดินไปหน้าอาคารบนแมพหลักเหมือนเดิม (`nearEnough()` guard ไม่เปลี่ยน) →
กดโต้ตอบ → โมดัลเดิมที่มีอยู่แล้ว (`renderModal()`) เปลี่ยนพื้นหลังจากกล่องข้อความธรรมดา
เป็น **ภาพตัดขวางแบบไดโอราม่า** (เห็นทั้งนอก-ในภาพเดียว สไตล์บ้านตุ๊กตาไม้ DIY) — ไม่มี
sub-map ไม่มีระบบเดินในร้าน ไม่มี loading screen ใดๆ ทั้งสิ้น

**ทำไมเลือกทางนี้ (ไม่ใช่ sub-map จริง):**
- ไม่ต้องสร้างระบบแมพซ้อนแมพใหม่ทั้งชุด (collision/pathing/asset แยกต่อร้าน)
- ใช้ท่อเดิมที่มีอยู่แล้ว (`interact()` → `renderModal()`) ได้ 100% แค่เปลี่ยนสิ่งที่ render
  ข้างในโมดัล
- คงกฎ cozy/ไม่มี fail state — งานเบา ไม่เพิ่มความเสี่ยง bug ใหม่

**กติกาสำคัญ — ต้องเป็น "ฉากคอมโพสท์" ไม่ใช่ "ภาพวาดจบภาพเดียว":**
ห้ามใช้ AI-gen หรือวาดภาพร้านสำเร็จรูปทั้งภาพ เพราะจะตกแต่งเองไม่ได้ (ขัดกับ §5.4
ที่ผู้เล่นต้องวางเฟอร์ได้อิสระ) โครงสร้างที่ถูกต้องคือ:

```
พื้นหลังไดโอราม่า (คงที่ 1 ชิ้น — ผนัง/พื้น/หลังคาตัดขวาง)
        +
เฟอร์แต่ละชิ้น (แยกสไปรท์ วางทับตามกริดที่ผู้เล่นจัด)
        +
NPC sprite (ตำแหน่งตามกฎข้อ 3/4 ด้านล่าง)
```

## 2. อาคารร้านค้า (26 ร้าน craft) — NPC บุคลิก

ใช้ระบบไดโอราม่าข้อ 1 ตรงๆ ไม่มีอะไรพิเศษเพิ่ม ยกเว้นเรื่องแอนิเมชัน NPC:

| กลุ่ม | จำนวน | NPC ทำอะไรในไดโอราม่า |
|---|---|---|
| **NPC บุคลิกเต็ม** (ตาม §3.6) | 3–5 ตัวนำร่อง | **ขยับวนลูปเบาๆ** (สลับ 2-3 ท่า/ขยับซ้าย-ขวานิดหน่อยเป็นรอบ — **ไม่ใช่** pathfinding เดินอิสระ) |
| ร้าน craft ที่เหลือ | ~21 ร้าน | ยืนนิ่งจุดเดียว ไม่ลงทุนแอนิเมชัน |

## 3. ด่านนอกอาคาร (farm / animal / forest) — โครงสร้างแบบ "ชั้นซ้อน"

ต่อยอดจาก §5.3 (วงจรบูรณะ 4 ขั้น) — ขั้น "วางเฟอร์" ของด่านนอกอาคารแตกเป็น 4 ชั้นย่อย
ต้องคิดทีละชั้น อย่าคิดพร้อมกันหมด (นี่คือเหตุผลที่ด่านนอกออกแบบยากกว่าร้าน — มีเงื่อนไข
ซ้อนกันหลายชั้นพร้อมกัน ต่างจากร้านที่เป็นแค่กล่องตกแต่งล้วนๆ):

| ชั้น | คืออะไร | บังคับ/อิสระ |
|---|---|---|
| 1. ฟังก์ชัน | พื้นที่ผลผลิตเกิดจริง (เช่น แปลงผัก 9 ช่องของ farm_a) | บังคับ ตายตัว ไม่ใช่เรื่องสวย |
| 2. ขอบเขต | รั้ว + ป้ายด่าน | บังคับ — ปิดจบขั้นบูรณะ |
| 2b. **กระท่อม** (ใหม่) | บ้านของ NPC ผู้ผลิต วางที่ไหนในด่านก็ได้ | บังคับ — เป็นตัวแทนว่า "NPC ย้ายมาอยู่แล้ว" |
| 2c. **จุดยืน NPC** (ใหม่) | เฟอร์ **แยกชิ้นจากกระท่อม** เช่น ม้านั่งทำสวน/รางอาหารสัตว์/ม้านั่งริมกองไฟ (ตามธีม `cat`) | บังคับ — วางตรงไหน NPC ไปยืน/ทำงานตรงนั้นบนแมพจริง |
| 3. ทางเดิน | เว้นอย่างน้อย 1 ช่องรอบด่านเสมอ (กฎเดิม CLAUDE.md ข้อ 4) | บังคับ (เช็คก่อนปิดจ๊อบ) |
| 4. ตกแต่งอิสระ | ม้านั่ง กระถาง หุ่นไล่กา ฯลฯ | อิสระ 100% cosmetic ล้วน ไม่มีผลต่อ gameplay |

**เหตุผลที่แยก "กระท่อม" กับ "จุดยืน NPC" เป็นคนละชิ้น** (ยืนยันแล้วกับพี่แยม):
ให้ผู้เล่นจัดคอมโพสท์ฉากได้อิสระกว่า — กระท่อมอยู่มุมหลังก็ได้ แต่ NPC ยืนทำงานเห็นชัดๆ
ข้างแปลงผักด้านหน้าได้ ไม่ผูกติดกัน

**ผลต่อจำนวนเฟอร์บังคับ:** เดิมคุยกันไว้ (รอบก่อน) farm_a มี **5 เฟอร์บังคับ** — ตอนนี้ต้อง
ทบทวนใหม่เพราะเพิ่มกระท่อม+จุดยืน NPC เข้าไป ขั้นต่ำกลายเป็น **รั้ว + ป้าย + กระท่อม +
จุดยืน NPC = 4 ชิ้น** (ของเดิมอาจมีมากกว่านี้ เช่น ทางเข้า) ยังไม่ได้ finalize ตัวเลขสุดท้าย

## 4. ข้างในกระท่อม — ก็เป็นไดโอราม่าเหมือนกัน แต่ไม่มีเฟอร์บังคับ

เดินไปกระท่อม (ที่วางไว้ตามข้อ 3) → กดโต้ตอบ → เปิดไดโอราม่าข้างในแบบเดียวกับร้านค้า
(ข้อ 1) — วางเฟอร์ตกแต่งได้อิสระ (เตียง โต๊ะ พรม โคมไฟ ของส่วนตัว)

**ต่างจากร้านค้า/นอกบ้านตรงนี้:** ✅ **ไม่มีเฟอร์บังคับเลยสักชิ้น** — ข้างในกระท่อมเป็น
"ของแถมสำหรับคนอยากแต่งเพิ่ม" เท่านั้น ไม่ผูกกับการปิดจ๊อบบูรณะใดๆ (ตัวกระท่อม+จุดยืน
NPC ในข้อ 3 ทำหน้าที่ปิดจ๊อบไปแล้ว)

**ตำแหน่งยืนของ NPC ข้างในกระท่อม:** **วาดติดไว้ในภาพพื้นหลังไดโอราม่าเลยตั้งแต่แรก**
(เช่น นั่งมุมหน้าต่าง/ยืนข้างเตาผิง) เป็นส่วนหนึ่งของกรอบที่ไม่เปลี่ยน — **ไม่ให้ผู้เล่น
เลือกเอง ไม่สุ่ม** เหตุผล:
- ให้เลือกเอง = สร้างขั้นตอนบังคับใหม่ในพื้นที่ที่ตั้งใจให้ไม่บังคับ ขัดกับเป้าหมาย
- สุ่ม = ตำแหน่งขยับทุกรอบที่เข้า ดูแปลก ไม่ cozy (บ้านควรรู้สึกเซ็ตอยู่กับที่)
- วาดตายตัว = ศูนย์ mechanic ใหม่ ใช้แพทเทิร์นเดียวกับข้อ 1 เป๊ะ (กรอบคงที่ + เฟอร์ลอยทับ)

## 5. เรื่องที่ตัดสินใจไปแล้วก่อนหน้านี้ (บริบทประกอบ ไม่ต้องออกแบบซ้ำ)

- ❌ **ไม่ทำ "วาปเข้าไปคุยกับ NPC" โดยตรง** — ระบบวาร์ปโซน (v1.3.0) + สมุดบันทึกแจ้งเตือน
  (v1.12.0, ติ๊ก opt-in ต่อด่าน) แก้ปัญหา "ต้องไปคุยกับใครตอนไหน" ไปแล้ว วาปตรงจะซ้ำซ้อน
  และขัดกับ core loop ที่ตั้งใจให้เดินสำรวจ
- 💡 **ไอเดียแยกแมพเป็น 5 ผืน** (เมืองหลวง+4 ทิศ แทนกริดเดียว 50×50 ต่อเนื่อง) — ดีและ
  เข้ากับสถาปัตยกรรมเดิม (วาร์ปกลายเป็นจุดโหลดฉาก) แต่ **ยังไม่ตัดสินใจ**: เดินข้ามโซนที่
  ขอบแมพได้เลย หรือบังคับผ่านวาร์ปเท่านั้น — ทิ้งไว้เป็นคำถามเปิด
- ✅ เวลาเกม (`G.time`/`G.day`) ไม่ผูกกับโซนที่มองอยู่อยู่แล้ว (พิสูจน์จาก idle production
  ที่ทำงานครบทั้ง 63 ด่านตลอดเวลา) — ถ้าแยกแมพจริง แค่ย้ายไปเป็น state กลางที่ไม่ถูก
  ทำลายตอนสลับฉาก (Unity: Singleton/DontDestroyOnLoad)
