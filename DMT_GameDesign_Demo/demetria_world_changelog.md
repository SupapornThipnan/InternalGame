## v1.16.2 — เอาปุ่ม +/−/ฝาก-เบิกต่อช่องออกจากคลัง (ลากวางแทนที่ทั้งหมด) ✅ (ล่าสุด)
**การ์ดคลังโล่งขึ้น เพราะลากวางระบุจำนวนได้อยู่แล้ว**

- พี่แยมทักว่าปุ่มปรับจำนวน (−/94/+) กับปุ่ม "ฝาก ▸" ใต้ทุกช่องในคลังไม่จำเป็นแล้ว เพราะตอนย้ายด้วยการลาก (Drag & Drop, v1.16.0) ก็ระบุจำนวนเองได้อยู่แล้วผ่าน popup — เอาออกให้การ์ดดูโล่งขึ้น ไม่ซ้ำซ้อนกัน
- การ์ดสล็อตในคลัง (`.wh-slotcard`) เหลือแค่ **ไอคอน+ตัวเลขรวม กับชื่อไอเทมด้านล่าง** เท่านั้น ไม่มีตัวปรับจำนวนหรือปุ่มฝาก/เบิกฝังอยู่ในช่องอีกต่อไป — **ลากไปวางอีกฝั่งแล้วระบุจำนวนใน popup เป็นวิธีเดียวที่เหลือ**ในการย้ายของระหว่างกระเป๋ากับคลัง
- ลบฟังก์ชัน `whQtyStep()`/`whQtySet()` ที่ไม่มีจุดไหนเรียกใช้แล้วออกทั้งหมด (dead code) — `whDeposit()`/`whWithdraw()` ยังอ่าน `G.whQty` เหมือนเดิมทุกอย่าง เพราะนั่นคือจุดที่ `whDrop()` (ตอนลากวางแล้วกดยืนยัน) เขียนจำนวนที่เลือกไว้ให้อยู่แล้ว ไม่กระทบ contract เดิม
- ลดขนาด grid ของคอลัมน์ (`.wh-slotlist`) ให้แคบลงตามที่การ์ดไม่ต้องเผื่อที่ให้แถวปุ่มอีกต่อไป เห็นช่องต่อแถวได้เยอะขึ้น
- ปรับข้อความคำแนะนำหัวโมดัลเป็น "ลากช่องไปวางอีกฝั่งแล้วระบุจำนวนที่จะย้าย" ให้ตรงกับวิธีใช้งานจริงตอนนี้เพียงทางเดียว

### การตรวจสอบ
- ปรับเทสเดิม 2 ไฟล์ให้ตรงกับการเปลี่ยนแปลง:
  - `test_qty.js` — ส่วนทดสอบคลัง (8/8b/8c/8d/8e) เปลี่ยนจากเรียก `whQtyStep()`/`whQtySet()` เป็นตั้งค่า `G.whQty` ตรงๆ แทน (จำลองสิ่งที่ `whDrop()` ทำจริงตอนนี้) ยังคงยืนยัน clamp/key-แยกกัน/กระเป๋า-คลังเต็มครบทุกเคสเดิม
  - `test_invui.js` — ปรับ assertion ให้ยืนยันว่า **ไม่มี** ปุ่ม +/−/ฝาก-เบิกต่อช่องเหลืออยู่แล้ว (แทนที่จะเช็คว่ามี) และการ์ดยังลากได้ (`draggable="true"`) ตามเดิม
- regression: รันชุดเทสเดิมทั้ง 17 ไฟล์ที่เหลือ ผ่านครบทุกตัว — รวมทั้งหมด **511 assertion ผ่านหมด**

## v1.16.1 — ปรับขนาดช่องไอคอนในคลังให้เท่ากับช่องกระเป๋า ✅
**ให้ภาษาภาพของช่องไอคอนตรงกันจริงระหว่างกระเป๋ากับคลัง**

- พี่แยมทักว่าช่องไอคอน+ตัวเลขในโมดัลคลังเมืองหลวง (`.wh-slotcard .icon`) ใหญ่กว่าช่องในแผงกระเป๋า (`.inv-slot`) ทั้งที่ตั้งใจให้เป็นภาษาภาพเดียวกันตั้งแต่ v1.15.0 — สาเหตุคือช่องคลังเดิมยืดเต็มความกว้างการ์ดด้วย `aspect-ratio:1` ซึ่งกว้างกว่าช่องกระเป๋าเพราะการ์ดคลังต้องเผื่อที่ให้แถวปุ่มปรับจำนวนด้านล่างด้วย
- แก้ให้ช่องไอคอนในคลังเป็น **ขนาดคงที่ 46×46px** เท่ากับช่องกระเป๋าเป๊ะ ไม่ขึ้นกับความกว้างการ์ดอีกต่อไป พร้อมปรับ border-radius/font-size ของไอคอนและป้ายตัวเลขให้ตรงกับ `.inv-slot` ทุกอย่าง (9px/22px/10px)
- ตัวการ์ดรอบนอกยังกว้างพอสำหรับแถวปุ่ม −/+ และปุ่มฝาก/เบิกเหมือนเดิมทุกอย่าง เปลี่ยนแค่ขนาดไอคอนสี่เหลี่ยมด้านในให้เท่ากับกระเป๋าเท่านั้น

### การตรวจสอบ
- เป็นการแก้ CSS ล้วน ไม่กระทบ logic การฝาก/เบิก/ลากวางใดๆ
- regression: รันชุดเทสเดิมทั้ง 18 ไฟล์ (513 assertion) ซ้ำ ผ่านครบเหมือนเดิมทุกตัว

## v1.16.0 — คลังเมืองหลวง: ฝาก/เบิกด้วยการลาก (Drag & Drop) ✅
**ลากช่องของจากกระเป๋าไปวางที่คลัง (หรือกลับกัน) แล้วค่อยระบุจำนวน**

- พี่แยมขอให้ช่องเก็บของในคลังลากแล้วค่อยระบุจำนวนได้ — เพิ่ม **Drag & Drop** เป็นทางเลือกที่สองคู่กับปุ่ม +/− ▸ เดิมในโมดัลคลังเมืองหลวง (`#whModal`) **ไม่ได้แทนที่ของเดิม** กดปุ่มแบบเดิมได้ปกติทุกอย่างเหมือนก่อนหน้านี้
- ลากช่องสล็อตจากคอลัมน์ "🎒 กระเป๋า" ไปวางที่คอลัมน์ "🏰 คลัง" (หรือกลับกัน) → **เปิด popup ถามจำนวนก่อนย้ายจริงเสมอ** (ค่าเริ่มต้น = จำนวนที่มีทั้งหมด ปรับลดได้) ไม่ย้ายทันทีตอนวาง กันมือลั่นลากผิดแล้วของหายไปเงียบๆ
- ใช้โมดัล confirm ทั่วไป (`openConfirm()`) ตัวเดียวกับที่ระบบเซฟใช้ถามชื่อสล็อต/ยืนยันลบสล็อตอยู่แล้ว ไม่ต้องสร้าง popup ใหม่ซ้ำซ้อน
- วางกลับคอลัมน์เดิม (ลากจากกระเป๋าแล้ววางที่กระเป๋า) **ไม่ทำอะไรเลย ไม่เปิด popup** — กันการลากพลาดโดยไม่ตั้งใจ
- คอลัมน์ปลายทางไฮไลต์กรอบประสีทองระหว่างลากผ่าน (`.wh-col.drag-over`) ให้เห็นชัดว่ากำลังจะวางตรงไหน ส่วนการ์ดที่กำลังถูกลากจางลง (`opacity`) ให้รู้ว่ากำลังลากอันไหนอยู่
- ลากได้เฉพาะตอนยืนใกล้คลัง (`nearWarehouse()`) เหมือน guard เดิมของปุ่มฝาก/เบิกทุกจุด — **ไม่มีทางข้าม `nearEnough()` ผ่านทางลากได้** ยืนไกลจะลากไม่ติดตั้งแต่ `dragstart` เลย
- จำนวนที่ใส่ใน popup ถูก clamp ไม่ให้เกินของที่มีจริงเสมอ (พิมพ์เกิน/ค่าเพี้ยน → ปัดกลับเป็นจำนวนที่มีทั้งหมด) ใช้ตัวแปร `G.whQty` ชุดเดียวกับปุ่มเดิม ไม่มี state ซ้อนสองชุด

### เทสที่รันแล้ว (node จำลอง DOM + drag/drop event — 16 assertion ใหม่ ผ่านหมด)
- markup จริง: การ์ดมี `draggable="true"` + คอลัมน์รับ `ondrop` ครบทั้งสองฝั่ง ✅
- ลากจากกระเป๋าไปคลัง → เปิด popup ถามจำนวนจริง ของยังไม่ถูกย้ายทันที (ต้องกดยืนยันก่อน) ✅
- ยืนยันจำนวนบางส่วน (5 จาก 20) → ย้ายแค่ 5 จริง ไม่ใช่ทั้งหมด ✅ · ทิศทางตรงข้าม (ลากจากคลังไปกระเป๋า = เบิก) ทำงานถูกต้องเช่นกัน ✅
- วางกลับคอลัมน์เดิม → ไม่เปิด popup ไม่มีอะไรเปลี่ยน ✅
- ยกเลิกกลางทาง (`dragend` โดยไม่วาง) → state ถูกล้าง ไม่ค้างไปกระทบการลากครั้งถัดไป ✅
- ของ 0 ชิ้น → ไม่เปิด popup ✅ · ใส่จำนวนเกินที่มีจริง (999 ทั้งที่มีแค่ 10) → clamp เหลือแค่เท่าที่มีจริง ไม่ error ✅
- regression: รันชุดเทสเดิมทั้ง 17 ไฟล์ (497 assertion) ซ้ำ ผ่านครบหลังแก้ (ปรับ 2 assertion ใน `test_invui.js` ให้ตรงกับ attribute `draggable`/`ondragstart` ใหม่บนการ์ด) — รวมทั้งหมด **513 assertion ผ่านหมด**

## v1.15.0 — กระเป๋า/คลัง เปลี่ยนเป็น UI แบบสล็อตกริด ✅
**ปรับหน้าตาคลังของให้เป็นกริดช่องสี่เหลี่ยมตามภาพตัวอย่างที่พี่แยมส่งมา**

- พี่แยมส่งภาพตัวอย่าง UI คลังของสไตล์กริดช่องสี่เหลี่ยม (ไอคอน+ตัวเลขมุมล่างขวา เห็นช่องว่างที่เหลือด้วย) ขอให้ปรับทั้งกระเป๋าผู้เล่นและคลังเมืองหลวงตามแบบนี้ — ใช้**โครงสร้าง**ตามภาพ แต่ยึด**ธีมสีมืดน้ำเงิน/ทอง**ของเกมเดิมแทนโทนไม้อุ่นจากภาพตัวอย่าง ตามที่ตกลงกันไว้ (เพื่อให้เข้ากับ UI ส่วนอื่นของเกมที่เหลือ)
- แผงกระเป๋า (`#invPanel`) เปลี่ยนจาก pill-list เดิม (ชิปไอคอน+ชื่อ+ตัวเลขเรียงห่อบรรทัด) เป็น **กริดสล็อตสี่เหลี่ยม** — แต่ละสแตกของแต่ละไอเทมได้ 1 ช่อง โชว์แค่ไอคอน + ตัวเลขจำนวนเป็นป้ายเล็กมุมล่างขวา (ชื่อไอเทมย้ายไปเป็น `title` tooltip ตอนชี้เมาส์ค้างแทนที่จะเป็นตัวหนังสือถาวรในช่อง)
- **เห็นช่องว่างที่เหลือจริง** — จุดต่างสำคัญจากของเดิมที่ไม่แสดงอะไรเลยถ้ากระเป๋าว่าง ตอนนี้เรนเดอร์ครบทุกช่องตาม `G.bagSlots` เสมอ (ช่องที่มีของ + ช่องว่างเปล่าที่เหลือทั้งหมด) ให้เห็นระดับความเต็มของกระเป๋าได้ในทีเดียวแบบเกม inventory ทั่วไปสไตล์ Stardew/Minecraft
- ช่องที่ของครบสแตก (99 ชิ้น) ยังไฮไลต์กรอบ/สีตัวเลขต่างจากปกติเหมือนเดิม (สืบทอด class `max` จากระบบเดิม) — **ไม่มีอะไรเปลี่ยนด้าน logic การนับช่อง/สแตก** (v1.11.1) เลย เป็นแค่การแสดงผลใหม่ล้วนๆ
- คอลัมน์ "🎒 กระเป๋า" / "🏰 คลัง" ในโมดัลคลังเมืองหลวง (`#whModal`) เปลี่ยนจากลิสต์เรียงแนวตั้งเป็น **กริดการ์ดสล็อต** เช่นกัน — แต่ละการ์ดมีช่องไอคอน+ตัวเลขสี่เหลี่ยมด้านบน (ภาษาภาพเดียวกับกระเป๋า) ชื่อไอเทมด้านล่าง แล้วตามด้วยตัวปรับจำนวน + ปุ่มฝาก/เบิกครบเหมือนเดิมทุกอย่าง — **ฟังก์ชันการฝาก/เบิก/ปรับจำนวนไม่ถูกแตะเลย** เปลี่ยนแค่หน้าตาให้เป็นกริดแทนลิสต์
- ใช้ class ใหม่ (`.wh-slotlist` / `.wh-slotcard`) แยกจาก `.wh-item`/`.row1`/`.nm`/`.n` เดิมโดยเจตนา — โมดัลตลาดรับซื้อของ (`#marketModal`, v1.11.0) ที่ใช้ class ชุดเดิมร่วมกันมาตั้งแต่แรกจึงไม่ถูกกระทบเลย ยังเป็นลิสต์แนวตั้งแบบเดิมต่อไป (พี่แยมยังไม่ได้ขอเปลี่ยนจุดนี้ในรอบนี้)

## v1.14.1 — เอา overlay มืด/เบลอด้านหลังโมดัลร้าน/คลัง/ตลาดออก ✅
**มองเห็นเควส/HUD ด้านหลังได้ระหว่างเปิดโมดัลร้าน**

- เดิมเปิดโมดัลร้าน/คลัง/จุดวาร์ป/ตลาด (`#modal`, `#warpModal`, `#shopModal`, `#whModal`, `#marketModal`) จะมีฉากมืด+เบลอคลุมทั้งจอด้านหลังเสมอ (`rgba(4,8,14,.72)` + `blur(3px)`) — บัง HUD บนสุด, มินิแมพ, และวิดเจ็ตเควสหลักที่ลอยอยู่ตลอดเวลาไปหมด ทำให้มองไม่เห็นเควสที่ต้องส่งขณะกำลังดูสูตรคราฟในร้านอยู่
- เปลี่ยนพื้นหลังของ 5 โมดัลนี้เป็น **`background:transparent`** ตัดเงามืด+เบลอออกทั้งหมด — ตอนนี้มองเห็นแมพ/HUD/วิดเจ็ตเควสหลักด้านหลังโมดัลได้ตลอดเวลาที่เปิดอยู่
- ยังคลิกพื้นหลังเพื่อปิดโมดัลได้เหมือนเดิมทุกอย่าง (กลไก `onclick="if(event.target===this)closeModal()"` ไม่ถูกแตะเลย) — แก้แค่สีพื้นหลัง ไม่แก้กลไกคลิกปิด
- **ไม่แตะ** `#confirmModal` / `#clModal` (Changelog) / `#mapModal` — ยังมืด+เบลอเหมือนเดิม เพราะเป็นไดอะล็อกสั้นๆ ที่ตั้งใจให้โฟกัสเฉพาะหน้าต่างนั้นชั่วขณะ ต่างจากโมดัลร้าน/คลังที่มักเปิดค้างไว้นานระหว่างวางแผน

### การตรวจสอบ
- เป็นการแก้ CSS ล้วน ไม่กระทบ logic ใดๆ ในเกม
- regression: รันชุดเทสเดิมทั้ง 17 ไฟล์ (482 assertion) ซ้ำ ผ่านครบเหมือนเดิมทุกตัว (ไม่มีเทสไหนอ้างอิงค่าสี/backdrop-filter ของโมดัลโดยตรง)

- เพิ่มปุ่ม **"⏱️ ตั้งนาทีจริง/วันเกม"** ต่อจากหัวข้อ "⏰ เวลาในเกม" เดิมใน Dev Panel — พิมพ์ตัวเลขแล้วกด **มีผลทันทีตั้งแต่เฟรมถัดไป ไม่ต้องรีสตาร์ทเกมเลย** (เช่นตั้ง 1 = วันหมุนเร็วจี๋ เทสระบบผลิต/บิล/เควสรัวๆ ได้ในไม่กี่วินาที, ตั้ง 60 = ช้าลงเท่าตัวจากค่าปกติ)
- รีแฟกเตอร์ `loop()`: ดึงตรรกะเดินเวลา (บวก `G.time`, ตรวจข้ามวัน, เรียก `onNewDay()`) ออกมาเป็นฟังก์ชันแยก **`tickGameTime(dt)`** ใช้สูตร `dt*G.speed/(G.dayMinutes*60)` แทนการ hardcode `DAY_SECONDS` — ผลพลอยได้: เทสเรียกฟังก์ชันนี้ตรงๆ ได้เลย ไม่ต้องพึ่งพา `requestAnimationFrame` จริงเหมือนก่อน
- `DAY_MINUTES` (ค่าคงที่เดิมจาก v1.13.1) ยังอยู่เหมือนเดิมทุกอย่าง เป็นแค่ **ค่าเริ่มต้น** ตอนเปิดเกมใหม่ — `G.dayMinutes` เป็นสำเนาที่ปรับสดได้ระหว่างเล่น คนละตัวกัน ไม่กระทบกัน เปิดเกมใหม่ (รีเฟรชหน้า) ก็กลับไปที่ค่าเริ่มต้น 30 เสมอ
- เป็นเครื่องมือปรับจูน/ทดสอบเหมือน `speed`/`paused` เดิม — **ไม่บันทึกลงเซฟ** เลย (`serializeGame()`/`applySave()` ไม่แตะฟิลด์นี้) โหลดเซฟไหนก็ใช้ `DAY_MINUTES` ค่าเริ่มต้นเสมอ จนกว่าจะตั้งใหม่เองในเซสชั่นนั้น
- ค่า input เพี้ยน (ติดลบ/ว่าง/ไม่ใช่ตัวเลข) ถูก clamp ขั้นต่ำ 1 หรือ fallback กลับไปที่ `DAY_MINUTES` ไม่ทำให้เวลาหยุดเดินหรือพังทั้งเกม
- ยังอยู่ใน Dev Panel เดิมตามกฎ Dev Tools ทั้งหมด (GAME_DESIGN 13) — **ไม่ใช่ฟีเจอร์ผู้เล่นจริง** ต้องถอด/ซ่อนก่อนแจกจ่าย build จริงเหมือนปุ่ม Dev อื่นๆ ทุกปุ่ม

- อัปเดต GAME_DESIGN ข้อ 7 ให้อ้างอิงชื่อค่าคงที่ใหม่ (`DAY_MINUTES`) แทน `DAY_SECONDS`

## v1.13.0 — ปรับความเร็วเวลาเกม (DAY_SECONDS) + Dev Tools ควบคุมเวลา ✅
**แก้ปัญหาจริงที่พี่แยมเจอ: หน้าต่างเปิดร้านสั้นเกินไปจนทำอะไรไม่ทัน**

- ปัญหาเดิม: 1 วันเกม = **60 วินาทีจริง** ที่ speed 1x — ร้านที่เปิด 9 ชม./วัน (เช่นร้านขนมปัง 05:00–14:00) เหลือแค่ **~22 วินาทีจริง** ให้เดินไปคราฟ/ส่งเควส สั้นเกินไปจริง
- ปรับ **`DAY_SECONDS` จาก `60` เป็น `1800`** (30 นาทีจริง/วัน ที่ speed 1x) — แก้จุดเดียวตรงที่ประกาศค่าคงที่ ตรวจสอบแล้วไม่มีจุดอื่นในโค้ด hardcode ค่านี้ซ้ำ ตอนนี้หน้าต่าง 9 ชม. ≈ **11 นาทีจริง** ทำอะไรทันขึ้นมาก (ที่ 3x/8x เร็วกว่านี้ตามสัดส่วนเดิม)
- เพิ่ม section ใหม่ **"⏰ เวลาในเกม"** ใน Dev Panel (GAME_DESIGN 13) 2 เครื่องมือ:
  - **🕐 ตั้งชั่วโมง** (`devSetHour()`) — พิมพ์ชั่วโมง (0–23) แล้วเซ็ต `G.time` ตรงๆ **ในวันเดิม** ไม่ขยับ `G.day` ไม่เรียก `onNewDay()` เลย ใช้ทดสอบว่าร้านเปิด-ปิดตรงเวลาไหมแบบแม่นยำ ไม่ต้องรอเวลาไหลจริงหรือกดข้ามวันทั้งวัน
  - **⏩ ข้ามไปข้างหน้า** (`devSkipTime()`) — พิมพ์จำนวนชั่วโมงที่จะข้าม โดย**เรียก `onNewDay()` ทุกครั้งที่ข้ามผ่านวัน ไม่ใช่ครั้งเดียวตอนจบ** (`while(G.time>=1){G.time-=1;G.day++;onNewDay();}`) — ถ้าข้าม 48+ ชม. ทีเดียวแล้วเรียก `onNewDay()` แค่ครั้งเดียว ผลผลิต/บิลค่าเช่าส่งของ/รอบเควสจะตกไปเหลือแค่วันเดียว ไม่ตรงกับพฤติกรรมที่รอเวลาไหลจริงจะได้
  - ทั้งสองปุ่มเรียก `render()`/`updateHUD()` ทันทีหลังกด (+ `renderModal()`/`renderWhModal()`/`renderPanels()` ถ้ามีโมดัล/แผงเปิดค้างอยู่ตอนนั้น) ให้ HUD/นาฬิกา/ป้ายร้านเปิดปิดอัปเดตเห็นผลทันทีไม่ต้องรอเฟรมถัดไป
- ยังอยู่ใน Dev Panel เดิมตามกฎ Dev Tools ทั้งหมด — **ไม่ใช่ฟีเจอร์ผู้เล่นจริง** ต้องถอด/ซ่อนก่อนแจกจ่าย build จริงเหมือนปุ่ม Dev อื่นๆ ทุกปุ่ม

## v1.11.1 — ของชนิดเดียวกันเกิน 99 ชิ้น เปิดสแตกใหม่แทนโดนตัดทิ้ง ✅

## v1.10.0 — คลิกลากเดินได้ (Virtual Joystick) ✅
**เพิ่มการควบคุมด้วยเมาส์แบบ click-drag นอกเหนือจาก WASD/ลูกศรเดิม**

### กลไก
- กดเมาส์ซ้ายค้าง (mousedown บน canvas) แล้วลาก → ตัวละครเดินไปทิศที่ลาก ปล่อยเมาส์ = หยุดทันที
- เพราะกล้องล็อคกึ่งกลางจอไว้ที่ตัวละครทุกเฟรมอยู่แล้ว (`render()` เดิม) ทิศทางลากจึงคำนวณจาก "ตำแหน่งเมาส์เทียบกับจุดที่กดครั้งแรก" ตรงๆ ได้เลย — ไม่ต้องรู้ตำแหน่งตัวละครบนจอแยกต่างหาก เพราะตัวละครอยู่ตรงกลางจอเสมอ
- **deadzone 4px** กันสั่น: ลากน้อยกว่านี้ยังนับเป็นคลิกปกติ (เปิดตึก/จุดวาร์ปเหมือนเดิมทุกอย่าง) ไม่ใช่การลากเดิน
- แปลงพิกัดจอ → พิกัดกริดไอโซด้วยการผกผันสมการ `toScreen()` ที่มีอยู่แล้ว (`toScreen(dx,dy)={sx:(dx-dy)*(TW/2), sy:(dx+dy)*(TH/2)}` แก้สมการย้อนกลับ) แล้วส่งผลลัพธ์เข้า logic เดินเดิมของ `movePlayer()` ชุดเดียวกับ WASD เป๊ะ — ทั้งการ normalize ความเร็ว, กันชนตึก (wall-slide), และคำนวณทิศหันหน้าตัวละคร ไม่มีระบบเดินซ้อนสองชุดให้ต้องดูแลคู่กัน
- ความเร็วคงที่เท่า WASD เสมอไม่ว่าจะลากไกลแค่ไหน (แค่ทิศทางเท่านั้นที่มาจากระยะลาก ไม่ใช่ความเร็ว)

### กันชนกับของเดิม
- **WASD ชนะเสมอ** ถ้ากดค้างพร้อมกับลากด้วย — กติกาง่ายที่สุดสำหรับ edge case ที่ไม่ค่อยเกิด กันทิศมั่ว
- **ไม่เปิดตึกซ้ำตอนปล่อยเมาส์หลังลาก** — click event ที่ browser ยิงตอน mouseup หลังลากจะถูกกลืนไปครั้งเดียว (เช็คจาก flag `wasDragging`) คลิกเฉยๆ ที่ไม่ได้ลากยังเปิดตึก/จุดวาร์ปได้ปกติทุกอย่างเหมือนเดิม
- guard เดิมทั้งหมด (`openStage/openWarp/openShop/openWh/confirmOpen` freeze การเดิน) ใช้ร่วมกับการลากด้วย เพราะรวมเข้า `movePlayer()` ฟังก์ชันเดียวกัน ไม่ต้องเพิ่ม guard ซ้ำ

### UI
- วงกลมโปร่งแสง (base) โผล่ตรงจุดที่กดเมาส์ลงครั้งแรกพอดี + เข็ม (knob) สีทองขยับตามทิศที่ลาก ลากไกลเกิน 40px เข็มจะค้างที่ขอบวง (ทิศยังอัปเดตต่อได้ปกติ)

### หมายเหตุ
- รอบนี้รองรับ**เฉพาะเมาส์**ตามที่คุยกันไว้ ยังไม่รองรับทัชจอ (มือถือ/แท็บเล็ต) — ถ้าต้องการเพิ่มทีหลังใช้ Pointer Events แทนที่ mouse events ได้โดยโครงสร้างเดิมไม่ต้องเปลี่ยนมาก

## v1.5.0 — คลังประจำด่าน (ระบบคลัง เฟส 2) ✅
**เปลี่ยน passive stage เป็น idle accumulation — ผลิตสะสมเองแม้ผู้เล่นไม่อยู่**
(เฟส 3 คือคลังเมืองหลวง/ขนของ/เช่าส่ง ยังไม่ทำในรอบนี้)

### โมเดลใหม่ (Model A)
- แต่ละ passive stage มี `s.storage` (ไอเทม→จำนวน) กับ `s.storageTier` · ความจุคำนวณจาก `storageCap(s) = 30 + tier×30` **นับเป็นจำนวนชิ้นรวมทุกชนิด** (ต่างจากกระเป๋าที่นับเป็นช่อง/ชนิด)
- **`onNewDay()` กลายเป็น idle production tick** — วนทุกด่านที่เริ่มผลิตแล้ว ไม่สนใจว่าผู้เล่นอยู่ไหนหรือเปิดโมดัลอะไรค้างไว้ ครบ `growDays` เมื่อไหร่ก็ฝากผลผลิตลงคลังด่านแล้ว **reset `daysGrown=0` เข้ารอบใหม่ทันที** วนเองไปเรื่อยๆ
- คลังเต็ม → ด่าน **พักผลิต** (ข้าม tick ตั้งแต่ต้น ไม่นับวันเพิ่ม) จนกว่าผู้เล่นจะมาเก็บ แล้วเดินเครื่องต่อเอง
- ล้น cap → ใส่เท่าที่พอดี ไม่เกินแม้แต่ชิ้นเดียว
- **คลังด่าน ≠ กระเป๋า** เป็นคนละถังโดยตั้งใจ: ด่านฝากของลงคลังได้แม้กระเป๋าผู้เล่นเต็ม — นี่คือหัวใจที่ทำให้ปล่อยด่านทิ้งไว้ผลิตได้จริง

**DECISION 1 — ปุ่มปลูก:** ทำตามที่น้องโค่แนะนำ คือให้ `plant` เป็น**สวิตช์เปิดการผลิตครั้งเดียว** (กดครั้งแรกครั้งเดียว จากนั้นวนผลิตเองตลอด ไม่ต้องปลูกซ้ำ) ปุ่มเปลี่ยนข้อความเป็น "🌱 เริ่มผลิต" ถ้าพี่แยมอยากให้ auto-on ตั้งแต่ปลดล็อคเลย บอกได้ แก้บรรทัดเดียว

### เก็บผลผลิต
- `doHarvest()` เดิม → **`doCollect()`** ย้ายของจากคลังด่านเข้ากระเป๋าผ่าน `addItem()` ของเฟส 1 ทีละชนิด หักออกจากคลังเท่าที่ `addItem()` รับได้จริง
- กระเป๋าเต็ม/สแตกตัน → ของ**ไม่หาย** ค้างในคลังด่านต่อ · เก็บได้บางส่วนก็บอกใน toast ว่าที่เหลือยังค้างอยู่
- ไม่ต้อง reset `daysGrown` หลังเก็บ เพราะด่านที่พักอยู่จะอยู่ที่ 0 เสมออยู่แล้ว (รอบที่ทำให้คลังเต็ม reset ไปก่อนหน้าจะหยุด) — ใส่คอมเมนต์อธิบายไว้ในโค้ดแล้ว

### UI
- โมดัลด่าน: "📦 คลังด่าน X/30 ชิ้น" + แถบ fill (เต็ม = แดง) + รายการไอเทมที่กองอยู่ + สถานะ `⚙️ กำลังผลิต (อีก N วัน)` / `🛑 คลังเต็ม — หยุดผลิต` · ปุ่ม "🧺 เก็บผลผลิต (N ชิ้น)" disabled เมื่อคลังว่าง
- บนแมพ (`drawBuilding`): เดิมโชว์ ✨ ตอน `ready` → เปลี่ยนเป็น **✨ เมื่อมีของรอเก็บ** และ **📦 บนรัศมีแดงเมื่อคลังเต็มหยุดผลิต** มองออกแต่ไกลว่าด่านไหนตันรออยู่
- prompt ตอนเดินเข้าใกล้เปลี่ยนตามสถานะจริง (เก็บผลผลิต / ดูคลังด่าน / เริ่มผลิต)

### ขยายคลัง (money sink)
- ปุ่มในโมดัลด่าน จ่ายครั้งเดียวจบ (ไม่ใช่เช่า) +30 ชิ้นต่อครั้ง ราคา `STORAGE_PRICES=[800, 2000, 4500]` ขยายได้ 3 ครั้ง → เพดาน 120 ชิ้นต่อด่าน · เก็บระดับใน `s.storageTier` · มี `nearEnough()` guard

### สิ่งที่ลบออก
- ฟิลด์ `s.ready` **ถูกลบทิ้งทั้งระบบ** (grep ยืนยันเหลือ 0 reference) — ด่านไม่มีสถานะ "โตเสร็จแล้ว" อีกต่อไป มีแค่ "ในคลังมีของเท่าไหร่"

### เทสที่รันแล้ว (node จำลอง DOM — 52 assertion ผ่านหมด)
- ยังไม่กดเริ่มผลิต ข้าม 5 วันไม่มีของ ✅ · กดเริ่ม → วันที่ 1/2/3 ได้ 9/18/27 ชิ้น ผลิตต่อเองไม่ต้องปลูกซ้ำ ✅
- ชน cap ที่ 30 พอดีไม่ล้น ✅ · ข้ามต่ออีก 10 วันยังคง 30 และ `daysGrown` ไม่เดิน ✅

- เก็บตอนกระเป๋าว่าง → เข้ากระเป๋าครบ 30 ชิ้น/3 ช่อง คลังว่าง ผลิตต่อวันถัดมา ✅
- **คลังเต็ม + กระเป๋าเต็ม → กดเก็บแล้วของไม่หายทั้งสองถัง** (snapshot เทียบ byte-for-byte) ✅

- regression: ของในคลังด่านคราฟตรงๆ ไม่ได้ ต้องเก็บเข้ากระเป๋าก่อน ✅ · ชุดเทสเฟส 1 (49 assertion) ยังผ่านครบหลังลบ `ready` ✅

## v1.4.0 — กระเป๋าระบบช่อง + ช่างเครื่องหนัง (ระบบคลัง เฟส 1) ✅
**เปลี่ยน inventory จากเก็บไม่จำกัด → ระบบ "ช่อง" พร้อม NPC ขายช่องเพิ่ม**
(เฟส 2-3 คือคลังด่าน/คลังกลาง ยังไม่ทำในรอบนี้)

### กระเป๋าระบบช่อง
- 1 ช่อง = ของ 1 **ชนิด** สแตกได้ถึง 99 ชิ้น · `G.bagSlots` เริ่มที่ 12 · ช่องที่ใช้ = จำนวนชนิดที่ `G.inv[k] > 0`
- helper กลาง `addItem(name, qty)` คืนจำนวนที่ใส่ได้จริง — ชนิดที่มีอยู่แล้วบวกเข้าสแตกเดิม (เพดาน 99), ชนิดใหม่ต้องมีช่องว่าง, เต็มแล้วคืน 0
- ทุกทางที่ได้ของเข้ากระเป๋าเดินผ่าน `addItem()` หมด: `doHarvest()`, `doCraft()`, และ `devAddItem()` (Dev Panel ตั้งใจให้ติดลิมิตด้วย จะได้ทดสอบเคสกระเป๋าเต็มจากตรงนั้นได้เลย) — เควสให้รางวัลเป็นเงินอย่างเดียว ไม่มีของ จึงไม่ต้องแก้
- แผงคลังของโชว์ `ใช้ไป X/12 ช่อง` ที่หัวแผง (แดงเมื่อเต็ม) และชิปที่สแตกครบ 99 ขึ้นตัวเลขแดง

**กันของหายตอนกระเป๋าเต็ม** (จุดที่ต้องระวังที่สุดของเฟสนี้):
- **เก็บเกี่ยว** — ถ้าใส่ไม่ได้เลยสักชนิด จะไม่รีเซ็ตแปลง ปล่อยให้ `ready` ค้างไว้ กลับมาเก็บใหม่ได้ · ถ้าใส่ได้บางส่วน เก็บเท่าที่ใส่ได้แล้วบอกใน toast ว่าตกหล่นกี่ชนิด
- **คราฟ** — หักวัตถุดิบก่อนแล้วค่อยลงผลลัพธ์ (เพราะวัตถุดิบที่หมดพอดีอาจ *ปลดช่องว่าง* ที่ผลลัพธ์ต้องใช้พอดี) ถ้าผลลัพธ์ยังลงไม่ได้จะ **rollback ทั้งชุด** คืนวัตถุดิบครบ ไม่มีทางที่วัตถุดิบหายฟรี

### NPC ช่างเครื่องหนัง 🧳
- เป็นวัตถุในโลกแบบเดียวกับ warp monument — **ไม่อยู่ใน `DEF`** และ **ไม่ลงทะเบียนใน `buildings{}`** จึงไม่บล็อคทางเดิน

## v1.3.0 — จุดวาร์ปข้ามโซน ✅

- **Placement:** พิกัดดิบข้างบนไม่รับประกันไม่ทับตึกที่ `placeStages()` วางไว้ — รีแฟกเตอร์ logic หาไทล์ว่างที่ใช้ตอนหาจุดสปอนผู้เล่น (`findSpotBeside`) ให้เป็นฟังก์ชันทั่วไป `findFreeTile(x0,y0)` รับพิกัดตรงๆ ใช้ snap ทั้งจุดสปอนผู้เล่น, จุดวาง `WARP_POINTS` ทั้ง 5, และจุดลงวาร์ป
- **State:** `G.unlockedZones` (Set) seed ด้วย `{'east'}` ตั้งแต่เริ่มเกม (farm_a unlocked:true อยู่แล้ว)
- **Trigger:** `checkZoneUnlock(s)` เรียกท้าย `doUnlock()` เช็คว่า stage ที่เพิ่งปลดตรงกับ `triggerId` ของ `WARP_POINTS` อันไหนไหม ถ้าใช่ → เพิ่มโซนเข้า `G.unlockedZones` + toast "🗺️ ค้นพบจุดวาร์ป [ทิศ] แล้ว!" — เรียกใน Dev Panel (`devUnlockNext`/`devUnlockStage`) ด้วยเพื่อทดสอบ flow เต็มได้โดยไม่ต้องเดินจริง
- **Render:** `drawWarpPoint()` วาดเป็นหินสลักในพาสเดียวกับ `drawBuilding()` (depth-sort ร่วมกับตึก/ผู้เล่นตามปกติ ไม่ทำแยก layer) — ล็อคอยู่ = หินเทาหม่น 🔒, ปลดล็อคแล้ว = เรืองแสงธีมสี `ZONE_META[zone].color` ตลอดเวลา (ไม่ใช่แค่กลางคืนแบบหน้าต่างตึก) ให้เห็นชัดว่าใช้งานได้ — ไม่ขึ้นทะเบียนใน `buildings{}` จึงไม่บล็อกการเดิน
- **Interact:** `findNearWarp()` คู่ขนานกับ `findNear()` เดิม กด E ใกล้จุดวาร์ปที่ปลดล็อคแล้วเปิด modal ใหม่ `#warpModal` (แยกจาก `#modal` เดิมที่ผูกกับ `G.openStage` กันชนกัน) โชว์รายชื่อโซนอื่นที่ปลดล็อคแล้ว (ไม่รวมโซนที่ยืนอยู่) เลือกแล้ววาร์ปทันที — จุดที่ยังล็อค กด E ได้แค่ toast บอกว่าต้องปลดล็อคด่านไหนก่อน ไม่เปิด modal เปล่า
- **กันโกง:** วาร์ปแก้แค่ `G.player.x/y` ไม่แตะ inventory/money/stage state ใดๆ — `nearEnough()` ของ `doPlant/doHarvest/doCraft/doUnlock/submitQuest` อ่านตำแหน่งผู้เล่นสดทุกครั้งอยู่แล้ว (ไม่มี cache) ทดสอบยืนยันด้วย node script จำลอง DOM แล้วว่ายังบังคับใช้ปกติ 100% หลังวาร์ป
- **กล้อง:** `render()` เดิม snap กล้องไปตำแหน่งผู้เล่นทุกเฟรมอยู่แล้ว (ไม่มี lerp/smoothing) วาร์ปจึงไม่มีอาการจอกระตุกหรือไถลข้ามแมพ — ไม่ต้องเพิ่มโค้ดจัดการกล้องเลย
- **เทสที่รันแล้ว (จำลอง DOM ด้วย node script, 36 assertions):** syntax check `new Function` ผ่าน ✅ · seed เริ่มเกมมีแค่ east ✅ · จุดวาร์ปทั้ง 5 ไม่ทับตึกและอยู่บนไทล์จริง ✅ · trigger ตรงตาราง (farm_a/npc_bread/forest_cave/forest_snow/animal_croc) ✅ · ปลดล็อค npc_bread → center โผล่พร้อม toast "ค้นพบจุดวาร์ป" ✅ · ยืนที่จุดวาร์ปตกที่ยังล็อค กด E → ไม่เปิด modal มีแค่ toast บอกเงื่อนไข ✅ · ปลดล็อค forest_cave → west ใช้ได้ → วาร์ปจากกลางไปตกสำเร็จ ยืนใกล้จุดวาร์ปจริง ไม่ติดตึก ✅ · วาร์ปไม่แตะ money/inventory ✅ · วาร์ปไปโซนที่ยังล็อค (north) ไม่ขยับผู้เล่นเลย ✅ · กด E ใกล้ตึกปกติ (farm_a) ยังเปิด `#modal` เดิมได้ถูกต้อง ไม่ชนกับ `#warpModal` ✅

**เกมไอโซเมตริกเดินได้จริงตัวแรก ต่อยอดจากดีไซน์ ECO System 63 ด่าน**

- **World Map**: สร้างแมพ 5 โซนตามเข็มทิศ (เมืองหลวงตรงกลาง / เหนือ=หิมะ / ออก=ฟาร์ม / ใต้=ลาวา / ตก=เหมืองแร่) ด้วย value noise ให้ขอบโซนเป็นธรรมชาติไม่กลมเป๊ะ พร้อมถนนเชื่อมเมืองหลวงออกไปทั้ง 4 ทิศ
- **วางด่านอัตโนมัติ**: ดึงข้อมูล 63 stage จาก `eco_demo.html` (ITEMS + DEF + zone) มาวางบนกริดตามโซนจริง ไม่ทับกัน ทุกด่านเดินถึงได้ (verify ด้วย flood-fill)
- **การเดิน**: ตัวละครเดิน WASD/ลูกศร ชนอาคารไม่ได้ (collision), กล้องตามตัวละครแบบ smooth
- **กลางวัน-กลางคืน**: ท้องฟ้าไล่สีตามเวลา, พื้นมืดลงตอนกลางคืน, หน้าต่างอาคารที่ปลดล็อคแล้วติดไฟเหลืองพร้อมแสงกองรอบๆ, ตัวละครถือโคมส่องทางตอนกลางคืน, ปุ่มปรับความเร็วเวลา 1x/3x/8x + pause
- **Inventory**: แผงคลังของ (กด I) แสดงไอเทมที่เก็บมาได้ทั้งหมด
- **Quest**: NPC ที่ปลดล็อคแล้วสุ่มออกเควสขอไอเทม (กด Q ดู) ปุ่มเควสเรืองทองเมื่อมีเควสที่ส่งได้ ส่งเควสได้ทั้งจากแผง Quest และจากในร้าน NPC โดยตรง
- **โต้ตอบด่าน** (กด E ใกล้อาคาร หรือคลิกอาคาร): ปลูก/รอ/เก็บเกี่ยวสำหรับ passive stage, คราฟตามสูตรสำหรับ craft stage, ดูเงื่อนไขปลดล็อคพร้อม cost breakdown
- **มินิแมพ**: มุมขวาบน หมุน 45° เป็นรูปเพชรพร้อมป้ายทิศ N/S/E/W, จุดชมพู=ตัวเรา, จุดทอง=อาคารปลดล็อคแล้ว, จุดเทา=ยังล็อค
