01

ภาพรวมระบบ

หัวใจของสถาปัตยกรรมนี้คือ ข้อมูลบ้านกับ mesh แยกออกจากกันคนละชั้น — world เป็นออบเจกต์เปล่า ๆ ที่ไม่รู้จัก three.js เลย ส่วนชั้น mesh มีหน้าที่แปลข้อมูลเป็นของที่มองเห็น แยกแบบนี้แล้วเซฟ ย้อน และโหลดกลับ ทำได้โดยไม่ต้องยุ่งกับฉากเลย — ตอนนี้ข้อมูลมี 5 หมวดแล้ว (พื้น ผนัง ช่องเปิด ของแขวนผนัง เฟอร์นิเจอร์) แต่หลักการเดิมยังใช้ได้ทุกหมวด

02

โมเดลข้อมูล

พื้นกับผนังเก็บเป็น dictionary ที่ใช้พิกัดเป็นคีย์ ไม่ใช่อาเรย์ — เพราะบ้านส่วนใหญ่มีช่องว่างเยอะ และการเช็คว่า "ตรงนี้มีของอยู่หรือยัง" ต้องเร็วมาก เพราะเรียกทุกครั้งที่เมาส์ขยับ ส่วนช่องเปิดกับของแขวนผนังเป็นอาเรย์ที่อ้างอิงกลับไปที่คีย์ผนัง แทนที่จะฝังอยู่ในตัวผนังเอง 

// ข้อมูลบ้านทั้งหลังหน้าตาแบบนี้ ไม่มี mesh ปนอยู่เลย
world = {
  floors:   { "3,-2": { mat: "oak" }, ... },                    // คีย์ = "x,z" ของช่อง
  walls:    { "h,3,-2": { paintOut: "sage", paintIn: "plaster" }, ... },  // ไม่มี type แล้ว!
  openings: [ { kind: "door", wall: "h,-1,3", offset: 0, width: 0.9 } ],
  wallArt:  [ { def: "frameSq", wall: "h,-2,-3", offset: 0, height: 1.7, side: 1 } ],
  objects:  [ { def: "sofa", x: 2.5, z: 1, rotY: 0, scale: 1, lift: 0 } ],
  foundation: false
}
วิวัฒนาการของฟิลด์ walls — v0.1.0–v0.5.x เก็บ { type: "door"|"window"|"solid", paint } ไว้ในตัวผนังเอง v0.6.0 ย้าย type ออกไปเป็น world.openings (ลบประตูแล้วผนังไม่หายทั้งช่วงอีกต่อไป) v0.7.0 แยก paint เดี่ยวเป็น paintOut/paintIn สองค่า — ทั้งสองรอบมีโค้ด migration ใน load() แปลงไฟล์เซฟรุ่นเก่าให้อัตโนมัติ ดูรายละเอียดที่หัวข้อ 12
03

กฎ Snap คู่ / คี่

กฎที่ยืมมาจาก Sims ตรง ๆ และเป็นจุดที่คนมักงงเวลาอ่านโค้ด: ของที่กว้างจำนวนช่องคี่ล็อกที่กลางช่อง ส่วนของที่กว้างจำนวนช่องคู่ล็อกที่เส้นกริด ทำแบบนี้แล้วขอบของทุกชิ้นจะตกลงบนเส้นกริดพอดีเสมอ ไม่ว่าจะกว้างเท่าไหร่ — แต่กฎนี้ใช้เฉพาะตอนกริดหยาบ 1 เมตร เท่านั้น รายละเอียดตอนปรับกริดให้ละเอียดกว่านั้นอยู่หัวขัดถัดไป

04

กริดที่ปรับความละเอียดได้

v0.9.0 เพิ่มตัวเลือกความละเอียดกริด 1 / 0.5 / 0.25 เมตร — ใช้ร่วมกันทั้งเฟอร์นิเจอร์พื้นและของแขวนผนัง (v0.11.0) ตั้งใจแยกวิธีคิดของค่า 1 กับค่าที่ละเอียดกว่าให้ชัด เพราะกฎ Sims (หัวข้อ 3) ใช้ได้แค่ตอน 1 เมตรเท่านั้น

furnGridวิธีคำนวณใช้ทำอะไร
1 (ค่าคงที่)กฎคู่/คี่แบบ Sims — ดูจากขนาดของค่าที่ตรงกับความรู้สึก "ต่อบล็อกกริด" ที่สุด
0.5 / 0.25round(px / g) * g ปัดตรง ๆ ไม่สนขนาดของจัดวางละเอียด ไม่ต้องพึ่งขนาดของชิ้น

ค่าเริ่มต้นตั้งแต่ v0.11.2 คือ 0.25 เมตร (เดิม v0.9.0 เริ่มที่ 1) — เปลี่ยนได้ที่แผงเครื่องมือเฟอร์นิเจอร์ตลอดเวลา สลับไปมาไม่กระทบของที่วางไปแล้ว มีผลแค่กับการวาง/ลากครั้งถัดไป

เส้นกริดย่อยในฉาก — เลือก 0.5 หรือ 0.25 จะเห็นเส้นตารางบางจริง ๆ ทับพื้น (ปั้นเองด้วยมือ ไม่ใช้ GridHelper ตรง ๆ เพราะฟังก์ชันเส้นปะมาตรฐานของ three.js คำนวณระยะสะสมข้ามเส้น ทำให้จังหวะเส้นประของแต่ละเส้นเหลื่อมกัน ต้องปั้น lineDistance เองให้รีเซ็ตทุกเส้น) เส้น 0.5 ม. เป็นเส้นทึบเข้ม (0.45) ส่วน 0.25 ม. เป็นเส้นปะจาง (0.28) — อ่านเป็นลำดับชั้นกริดหลัก/กริดย่อยชัดเจน โผล่เฉพาะตอนกำลังวาง/ลากของ ไม่รบกวนตอนทำอย่างอื่น
05

เส้นทางการวางเฟอร์นิเจอร์

ตั้งแต่นิ้วแตะจนของไปโผล่ในฉากและถูกเซฟ — ตอนนี้หมุนได้ 3 ทาง ไม่ใช่แค่ปุ่ม R

06

ประตู/หน้าต่าง: แยกจากผนัง

v0.6.0 รื้อออกจากของเดิมที่ผนังหนึ่งช่วง = ชนิดเดียว (type: "door") มาเป็น "งานปูน" กับ "งานไม้" คนละชั้น — ผนังมีหน้าที่แค่เว้นรูให้ถูกขนาด ส่วนวงกบ/บาน/กระจกเป็นของแยกที่แขวนอยู่บนรูนั้น

ประตู — เว้นรูจากพื้นถึง 2.05 ม.

แผงซ้าย/ขวาข้างช่องสูงแค่ระดับหัวประตู เหนือกว่านั้นเป็นคานทับหลังเต็มความกว้าง — บัวล่างมีแค่สองข้างของช่อง (ข้ามช่วงที่เป็นทางเดินไป) แต่บัวบนวิ่งเต็มความกว้างเสมอ

หน้าต่าง — เว้นรูแค่ช่วงกลาง

พื้นใต้ขอบล่าง (sill) กับด้านบนเป็นแผงเต็มความกว้างทั้งคู่ เพราะช่องหน้าต่างไม่ถึงพื้น — บัวล่างจึงวิ่งต่อเนื่องไม่ขาดเลย ต่างจากประตูที่บัวขาดเป็นช่วง (นี่คือของแถมที่ได้มาฟรีตอนแยกสถาปัตยกรรมใหม่)

07

เส้นทางการวาดผนัง

ผนังไม่ได้วางทีละก้อนแบบเฟอร์นิเจอร์ แต่ลากเป็นเส้นแล้วระบบตัดเป็นช่วงให้เอง และบังคับให้เป็นแนวตรงเสมอ เพราะบ้านที่ผนังเฉียงจะทำให้ระบบพื้น/หลังคาในอนาคตพังหมด

08

ทาสีแยกสองด้าน

v0.7.0 แยก paint เดี่ยวเป็น paintOut/paintIn — แต่ตั้งใจไม่ใช้คำว่า "ใน/นอก" ในตัวเกม เพราะระบบยังไม่รู้จักแนวคิด "ห้อง" เลยไม่มีทางรู้จริงว่าฝั่งไหนคือข้างในบ้าน (ดูหัวข้อ 15)

09

กายวิภาคผนัง และมุมที่เนียน

สองปัญหาที่เจอคนละช่วงเวลากัน แต่เป็นบทเรียนเรื่องเดียวกัน: อย่าให้พื้นผิวสองชิ้นอยู่ระนาบเดียวกันโดยไม่ตั้งใจ — ไม่ว่าจะเป็นซ้อนทับกัน (z-fighting) หรือขาดจากกัน (รอยบาก)

อัปเดต v0.6.0: ปัญหา "บัวขาดตรงประตู/หน้าต่าง" ที่เคยเขียนไว้ในหัวข้อนี้ตอน v0.5.0 แก้ไปแล้ว — ดูสาเหตุและวิธีคิดที่หัวข้อ 6 (การแยกผนัง/ช่องเปิดทำให้โค้ดทำบัวเหลือสาขาเดียว)
10

ของแขวนผนัง

v0.10.0 เพิ่มหมวดที่สาม (world.wallArt) ที่ไม่มีพิกัด X/Z ของตัวเองเลย — ตำแหน่งทุกอย่างอ้างอิงกับ ผนังที่แขวนอยู่ + ตำแหน่งในผนัง + ความสูง + ฝั่งที่คลิก ต้องแปลงพิกัดโลกไป-กลับพิกัดท้องถิ่นของผนังตลอดเวลา 

// แปลงพิกัดโลก → ท้องถิ่นของผนัง (ตอนคลิกวาง)
function worldToLocalOffset(rotY, dx, dz) {
  return rotY === 0 ? { lx: dx, lz: dz } : { lx: -dz, lz: dx };
}
// แปลงกลับ ท้องถิ่น → โลก (ตอนวาง mesh) พร้อมพลิกหน้าถ้าแขวนฝั่งตรงข้าม
function wallArtTransform(key, offset, height, side) {
  var t = wallTransform(key);
  var lx = offset, lz = side * WALLART_DEPTH;
  var d = t.rotY === 0 ? { dx: lx, dz: lz } : { dx: lz, dz: -lx };
  return {
    x: t.x + d.dx, y: floorY() + height, z: t.z + d.dz,
    rotY: t.rotY + (side < 0 ? Math.PI : 0)   // ฝั่งตรงข้าม = หมุนกลับหน้า
  };
}
ทำไม side ต้องพลิกหน้า 180° — ของแขวนทุกชิ้นปั้นให้หน้าตรงกับแกน local +Z เสมอ ถ้าแขวนฝั่ง local −Z (side = -1) แล้วไม่พลิก ผู้ชมที่ยืนอยู่ฝั่งนั้นจะเห็นด้านหลังของกรอบรูปแทน จึงต้องบวก Math.PI เข้าไปที่ rotY เพื่อให้หน้าเสมอหันออกหาคนดูฝั่งที่คลิกไว้เสมอ — ยืนยันด้วยสคริปต์ 12 เคส (2 แนวผนัง × 3 ตำแหน่ง × 2 ฝั่ง) ผ่านครบทุกเคส
11

วงจรชีวิตของ mesh

ข้อมูลหนึ่งชิ้นกลายเป็นของในฉากได้ยังไง และเมื่อไหร่ที่ต้องรื้อสร้างใหม่ทั้งหมด

12

Undo และการบันทึก

ทั้งสองอย่างใช้ฟังก์ชันแปลงข้อมูลตัวเดียวกันคือ plainState() ซึ่งคัดเอาเฉพาะข้อมูลเปล่า ๆ ออกมา ไม่มี mesh ติดไปด้วย — ตอนนี้ครอบคลุมครบ 5 หมวดแล้ว

13

โหมด เครื่องมือ และเคอร์เซอร์

โหมดเป็นตัวกำหนดว่าคลิกซ้ายทำอะไร ซึ่งเป็นเรื่องที่ต้องชัดเพราะกล้องกับเครื่องมือแย่งปุ่มเดียวกัน — ตั้งแต่ v0.7.2 เคอร์เซอร์ก็คำนวณจากสถานะเดียวกันนี้ด้วย

เครื่องมือpointerdown ทำอะไรลากแล้วทำอะไรcommit ตอนปล่อย
selectpickObject → pickOpening → pickWallArt แล้วเลือกย้ายของตาม snap (furn/wallart)save() ถ้าย้ายจริง
floorจำช่องตั้งต้นโชว์กรอบสี่เหลี่ยมcommitRect()
wallจำมุมกริดตั้งต้นโชว์เงาผนังตามเส้นcommitLine() → rebuildWalls()
openingเจาะช่องเปิดทันที (ถ้าว่าง)เจาะต่อทุกช่วงที่ลากผ่านsave() ถ้าเจาะโดนอย่างน้อยหนึ่ง
wallartแขวนทันทีตรงจุดที่คลิก——
paintทาช่วงที่ชี้อยู่ทันที (หน้าที่คลิกหรือทั้งคู่)ทาต่อไปเรื่อย ๆ ที่ลากผ่านsave() ถ้าทาโดนอย่างน้อยหนึ่งช่วง
furnวางทันทีหนึ่งชิ้น——
eraseลบของ → ช่องเปิด → ของแขวนผนัง → ผนัง → พื้น ตามลำดับ——
ระบบเคอร์เซอร์ (v0.7.2) — updateCursor() ตัดสินใจจากสถานะเดียวกับที่ตารางด้านบนใช้อยู่แล้ว: กำลังลากกล้อง/ลากของ (furn หรือ wallart) → มือกำ · โหมด Play → มือเปิด · เครื่องมือ "เลือก" ชี้โดนของที่เลือกได้ → นิ้วชี้ · เครื่องมืออื่นทุกตัว → กากบาท — ไม่มี state แยกใหม่ อ่านจากตัวแปรที่มีอยู่แล้วล้วน ๆ

แยกคลิก-จากลากด้วยเวลา+ระยะ (v0.8.0) — ขวาปล่อยโดยขยับไม่ถึง 5px และไม่เกิน 400ms นับเป็น "แตะ" (หมุนของ/เงา) ไม่ใช่ "ลาก" (หมุนกล้อง) ค่าทั้งสองใช้ร่วมกันทั้งตอนแตะของที่วางแล้วกับแตะเงาก่อนวาง (v0.11.1)
14

วงจรกลางวัน-กลางคืน

สไลเดอร์เวลาป้อนค่าชั่วโมงเข้า applySky() ตัวเดียว แล้วทุกอย่าง — ทิศแดด ความสว่าง สีฟ้า และไฟในบ้าน — คำนวณออกมาจากค่านั้นค่าเดียว (ไม่เปลี่ยนตั้งแต่ v0.1.0)

15

หนี้ทางเทคนิคและของที่ยังไม่มี

รายการนี้อัปเดตทุกครั้งที่พี่แยมสั่งให้ sync กับโค้ด (ไม่ใช่ทุกครั้งที่แก้โค้ดแล้ว — ดูหมายเหตุท้ายหน้า)

รู้อยู่แล้วว่ายังไม่ดี

  • หนึ่งช่วงผนังเจาะช่องเปิดได้แค่ชิ้นเดียว — คลิกช่วงที่มีช่องเปิดอยู่แล้วจะไม่ทำอะไร (hover แดงเตือนไว้ก่อน) ตั้งใจจำกัดสโคปไว้ตั้งแต่ v0.6.0
  • ของแขวนผนังปรับขนาดไม่ได้ — มีแค่ตำแหน่งแนวนอน+ความสูง ยังไม่มีสไลเดอร์ scale เหมือนเฟอร์นิเจอร์พื้น (v0.10.0 ตั้งใจตัดสโคปไว้ก่อน)
  • ของแขวนผนังชนกันได้ — ไม่เช็ก overlap ระหว่างชิ้น ต่างจากช่องเปิดที่กันไว้ 1 ชิ้น/ช่วง
  • ผนังที่ต่อกันกลางแนว (ไม่ใช่มุม) ยังวาดหน้าปลายซ้อนกันข้างใน — การอ้อมมุมของ v0.7.1 แก้เฉพาะปลายที่เจอมุมจริงเท่านั้น มองไม่เห็นแต่เปลืองสามเหลี่ยม ยังไม่คุ้มแก้
  • เซฟอยู่แค่ในเครื่อง — localStorage ผูกกับเบราว์เซอร์นั้น ย้ายเครื่องแล้วบ้านไม่ตามไป
  • มีฟังก์ชันตายค้างอยู่ — diningRugSmall() ไม่ถูกเรียกจากไหนเลย (ยังไม่ได้ลบ)

ยังไม่มีในระบบ

  • บ้านหลายชั้น — ต้องเพิ่มมิติ level เข้าไปในคีย์ทุกตัว กระทบทั้งไฟล์เซฟ
  • หลังคาและบันได — ทั้งคู่ต้องรู้จักรูปร่างห้อง ซึ่งตอนนี้ระบบยังไม่มีแนวคิด "ห้อง" เลย มีแค่ช่องพื้นกับช่วงผนัง
  • ระบบ "ใน/นอก" ของจริง — paintOut/paintIn (หัวข้อ 8) ตั้งชื่อตามหน้าผนังเฉย ๆ ไม่ได้รู้จริงว่าฝั่งไหนคือข้างในบ้าน เพราะไม่มีแนวคิด "ห้อง" เหมือนกัน
  • สระว่ายน้ำ ผนังโค้ง พื้นต่างระดับ
  • ตัวละครและ pathfinding — งานคนละก้อน ต้องคุยสโคปแยก
ข้อสังเกตสำหรับงานต่อไป — รายการ "ยังไม่มี" เกือบทั้งหมดผูกกันที่จุดเดียวคือ ระบบยังไม่มีแนวคิด "ห้อง" (พื้นที่ปิดล้อมด้วยผนัง) ถ้าจะทำหลังคา บันได ระบบชั้น หรือแม้แต่ให้ paintOut/paintIn รู้ความหมายจริงว่าฝั่งไหนคือข้างในบ้าน ควรสร้างตัวตรวจหาห้องจาก flood-fill บนช่องพื้นก่อน แล้วอย่างอื่นจะง่ายขึ้นทั้งหมด — ยังไม่ได้เริ่มงานนี้ รอคุยสโคปก่อน
