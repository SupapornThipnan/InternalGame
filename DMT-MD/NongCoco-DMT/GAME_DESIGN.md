## 1. เกมนี้คือเกมอะไร

**Demetria Spirit** เป็นเกม **life-sim / farming-sim แนวไอโซเมตริก 2.5D**
ผู้เล่นรับบทเป็นชาวเมืองที่ค่อยๆ ฟื้นฟูดินแดน Demetria ขึ้นมาใหม่
โดยการปลดล็อคพื้นที่ทีละด่าน สร้างห่วงโซ่การผลิต และรับใช้ผู้คนในเมือง

**อารมณ์ที่ต้องการ:** อบอุ่น น่ารัก ผ่อนคลาย ไม่มีการต่อสู้ ไม่มี fail state
ผู้เล่นเดินสำรวจ บูรณะด่าน เก็บของ คราฟของ ส่งเควส แล้วค่อยๆ เห็นเมืองกลับมามีชีวิต
(หมายเหตุ: ผู้เล่น**ไม่ได้ปลูกเอง** — NPC ประจำด่านเป็นคนผลิต · ดูข้อ 2 + 3.6)

**เกมอ้างอิงที่ชอบ:** Stardew Valley (loop การทำฟาร์ม), Emil Chronicle Online
(หน้าตา world map แบบ irregular grid), เกมมือถือเกาหลีแนว kawaii (ทิศทางศิลป์)

**แพลตฟอร์มปลายทาง:** Unity C# — ตอนนี้ prototype เป็น HTML เพื่อทดสอบ
ระบบเศรษฐกิจและ feel ก่อนลงทุนเขียน Unity จริง

## 2. Core Gameplay Loop

> 🔄 **ปรับทิศทางสำคัญ:** ผู้เล่น**ไม่ได้ปลูกเอง** — NPC ที่อยู่ประจำด่านเป็นคน
> ผลิตวัตถุดิบ ผู้เล่นรับบท **"ผู้ประสานเมือง"**: บูรณะด่าน → เก็บของ → คราฟ → ส่ง
> (ดูเหตุผล + บทบาท NPC ที่ข้อ 3.6)

```
บูรณะด่าน (ข้อ 5)  →  NPC ผู้ผลิตมาอยู่ประจำ  →  ผลิตวัตถุดิบสะสมในคลังด่าน (idle)
      ↑                                                    ↓
      │                                        ผู้เล่นเดินมาเก็บเข้ากระเป๋า
      │                                                    ↓
ปลดล็อค/บูรณะด่านใหม่  ←  ใช้ของ+เงิน  ←  ได้เงิน  ←  ส่งเควสให้ NPC  ←  คราฟที่ร้าน craft
```

**อธิบายเป็นคำ (บทบาทผู้เล่น = ผู้ประสาน ไม่ใช่ชาวนา):**

1. ผู้เล่น **บูรณะด่าน** (ข้อ 5) → **NPC ผู้ผลิต** ย้ายมาอยู่ประจำ เปิดฟาร์ม/คอก/ป่า
2. **NPC ผลิตวัตถุดิบเอง** สะสมในคลังประจำด่าน แม้ผู้เล่นไม่อยู่ (idle · ข้อ 4.5)
3. ผู้เล่นเดินมา **เก็บวัตถุดิบ** จากคลังด่านเข้ากระเป๋า
4. เอาวัตถุดิบไป **คราฟเองที่ craft stage** (ผู้เล่นคราฟ · NPC ร้านไม่ได้คราฟให้)
5. NPC สุ่มออก **เควส** ขอไอเทม — ผู้เล่นส่งแล้วได้เงิน
6. เอาเงิน+ของไป **บูรณะ/ปลดล็อคด่านถัดไป** → วนกลับข้อ 1 แต่เมืองกลับมามีชีวิตขึ้นเรื่อยๆ

**จุดสำคัญของ loop:** เงินมาจากเควสเท่านั้น (ยังไม่มีระบบขายของตรงๆ) · ผู้เล่นเป็น
คนกลางที่เชื่อมของจาก NPC ผู้ผลิต → คราฟ → ส่งให้ NPC ผู้บริโภค = เชื่อมเศรษฐกิจ
ทั้งเมืองกลับมา (ธีม "ฟื้นฟู Demetria")

## 3. ระบบ ECO — หัวใจของเกม

### 3.1 ประเภทของด่าน (Stage)

| ประเภท | `type` | ทำอะไร | ตัวอย่าง |
|--------|--------|--------|---------|
| **Passive** | `passive` | ปลูก/เลี้ยง → รอวัน → เก็บเกี่ยว ได้วัตถุดิบ 3 ชนิด | ฟาร์มพืชผัก, คอกม้า, ป่าไผ่ |
| **Craft NPC** | `craft` | ร้านค้าที่แปรรูปวัตถุดิบเป็นของใหม่ตามสูตร + ออกเควส | ร้านขนมปัง, โรงตีเหล็ก, หอดูดาว |

Passive แบ่งย่อยด้วย `cat` เป็น `farm` / `animal` / `forest` (มีผลกับ filter และธีมภาพ)

### 3.3 เงื่อนไขปลดล็อค

แต่ละด่าน (ยกเว้น 3 ด่านแรก) ต้องครบ **3 อย่างพร้อมกัน**:

1. **Prereq** — ด่านก่อนหน้าใน array ต้องปลดล็อคแล้ว (chain เป็นเส้นตรง 100%)
2. **ไอเทม** — `unlockCost` มักมีของคราฟ 2–3 ชิ้นจาก NPC ด่านก่อนหน้า + วัตถุดิบดิบ
3. **เงิน** — `moneyCost` ตาม Wave (ดูตารางข้างบน)

> **ทำไม chain เป็นเส้นตรง:** ตั้งใจให้ผู้เล่นไม่หลง และทำให้ระบบนำทาง
> "ด่านต่อไป" คำนวณได้ง่ายและถูกต้องเสมอ (`stages.find(s => !s.unlocked)`)
> ถ้าจะเปลี่ยนเป็น branching tree ในอนาคต ต้องเขียน logic หา next target ใหม่

### 3.4 Crafting Chain

ของบางอย่างต้องคราฟหลายทอด เช่น:

```
เนื้อกระต่าย + หอม + ขิง  →  ซุปกระดูก
ซุปกระดูก + ข้าวเจ้า      →  ราเมน
```

```
ถ่านหิน + หินแร่  →  เหล็กกล้า  →  ดาบ / โล่ / เกราะเหล็ก
```

ระบบเควสรู้จัก chain นี้ (วน loop จนกว่าจะไม่มีของใหม่เพิ่ม) จึงไม่มีทาง
ออกเควสขอของที่ผู้เล่นยังทำไม่ได้ — **กฎข้อนี้ห้ามพัง**

> 💡 **คราฟทีละหลายชิ้น:** หน้าต่างร้าน NPC มีตัวปรับจำนวน (− / พิมพ์เลข / +)
> ตั้งได้ 1–99 ก่อนกดคราฟ ไม่ต้องกดทีละ 1 แล้ว — สะดวกเวลาต้องสะสมของ
> เยอะๆ เพื่อไปปลดล็อคด่านถัดไปหรือปิดเควสรับจ้างที่ขอของคราฟจำนวนมาก

### 3.5 ระบบเควส — แยกเป็น 2 ชั้น

ตอนแรกมีแค่เควสสุ่มขอของอย่างเดียว แต่ผู้เล่นเทสต์แล้วสับสนว่าเควสที่เห็น
คือสิ่งที่ "ต้องทำ" เพื่อไปต่อหรือเปล่า จึงแยกแผงเควส (กด Q) เป็น 2 ก้อนชัดเจน:

**🎯 เควสหลัก** — ไม่ใช่เควสสุ่ม แต่คือ "ด่านล็อคถัดไป" (`nextUnlockStage()`
ตัวเดียวกับที่ขับเคลื่อนเข็มทิศในข้อ 8) แสดงของ/เงินที่ต้องใช้ตรงๆ บนการ์ด
กดปุ่ม "ดูวิธีไปปลดล็อค" เพื่อเปิด modal เดิม (เหมือนคลิกเข็มทิศ)
**ไม่มีปุ่มปลดล็อคตรงในแผง** — ต้องเดินไปถึงด่านจริงเสมอเพื่อรักษากฎ
`nearEnough()` ไม่ให้ปลดล็อคจากระยะไกลได้ ปลดล็อคด่านคือรางวัล ไม่มีเงินให้

**📜 เควสรับจ้าง** — ระบบเควสสุ่มเดิม NPC ที่ปลดล็อคแล้วสุ่มขอไอเทม 1–3 ชนิด:
- วัตถุดิบดิบ: 2–6 ชิ้น · reward 8–15 เหรียญ/ชิ้น
- ของคราฟ: 3–8 ชิ้น (คราฟทีเดียวได้หลายชิ้นแล้ว ดูข้อ 3.4) · reward 15–25 เหรียญ/ชิ้น
- จำกัดสูงสุด 12 ใบพร้อมกัน (ในเกมไอโซ) / 20 ใบ (ใน eco_demo)
- **NPC จะไม่มีวันขอของที่ร้านตัวเองคราฟอยู่แล้ว** — กรองออกจากพูลก่อนสุ่มเสมอ
  (กันความมั่ว เช่น ร้านขนมปังไม่ขอ "ขนมปัง" จากผู้เล่น) ถ้าร้านไหนกรองแล้ว
  พูลว่าง ข้ามไปลองร้านอื่น ไม่มีร้านไหนพอก็แค่ไม่ออกเควสรอบนั้น
- **ต้องเดินไปถึงร้าน NPC เจ้าของเควสก่อนถึงจะกดส่งได้** (`nearEnough()` guard
  เข้าแถวเดียวกับ ปลูก/เก็บเกี่ยว/คราฟ/ปลดล็อค) — เดิมกดส่งจากแผงเควสที่ไหน
  บนแมพก็ได้ ซึ่งเป็นช่องโหว่ที่แก้ไปแล้ว
- ส่งเควสสำเร็จ → เควสใบใหม่มาเร็วขึ้น

### 3.6 NPC ผู้ผลิต — ใครเป็นคนปลูก (ปรับทิศทาง)

**เดิม:** ผู้เล่นเดินไปกดปลูกเอง → **ใหม่:** NPC ที่อยู่ประจำด่านเป็นคนผลิต
ผู้เล่นแค่มาเก็บ ทำให้บทบาทผู้เล่นชัดขึ้นเป็น **"ผู้ประสานเมือง"** (ดู Core Loop ข้อ 2)

**ทำไมเข้ากับระบบเดิมเป๊ะ:**
- **v1.5.0 (idle production) รองรับอยู่แล้ว** — ด่านผลิตเองอัตโนมัติสะสมในคลัง
  แค่เปลี่ยนคำอธิบายจาก "ผู้เล่นปลูกแล้วโตเอง" → "NPC ประจำด่านเป็นคนปลูก"
  แทบไม่ต้องแก้กลไก · **ลบปุ่ม "เริ่มผลิต/ปลูก" ออก** (NPC ทำเอง)
- **ผูกกับระบบบูรณะ (ข้อ 5) + ธีมชาวเมืองกลับมา** — บูรณะฟาร์มเสร็จ → NPC ผู้ผลิต
  ย้ายมาอยู่ประจำ เปิดฟาร์มทำงาน = "ชาวเมืองที่หายไปกลับมา" ร้อยเป็นเรื่องเดียวกัน

**แบ่ง NPC เป็น 2 ระดับ (ไม่ต้องปั้น 63 ตัวเท่ากันหมด):**

| ระดับ | ใคร | ความละเอียด |
|---|---|---|
| **คนงานประจำด่าน** | NPC ที่ประจำ passive stage (ฟาร์ม/คอก/ป่า) | เรียบง่าย — ยืน/ขยับทำงานใกล้ด่านตัวเอง บทน้อย |
| **NPC บุคลิกเต็ม** | ร้าน craft สำคัญ + ตัวละครหลักของเมือง | มีชื่อ บุคลิก บทสนทนา เนื้อเรื่อง (เริ่ม 3-5 ตัวนำร่อง) |

**บทบาทผู้เล่นยังคง active:** โมเมนต์สร้างสรรค์ย้ายไปที่ **บูรณะ+แต่งฟาร์ม** (พี่สร้าง
มันขึ้นมา NPC แค่มาทำงานให้) + เก็บของ + **คราฟเอง** (ผู้เล่นคราฟที่ craft stage
เหมือนเดิม NPC ร้านไม่ได้คราฟให้ — NPC ผลิตแค่วัตถุดิบดิบ) + ส่งเควส

> 🚧 **สถานะ: ออกแบบแล้ว รอ implement** — ต้องมีข้อมูล NPC ผู้ผลิตต่อ passive stage
> (sprite/emoji, ตำแหน่งยืน, ระดับบุคลิก) · ทำหลังระบบบูรณะ (ข้อ 5) เพราะ NPC ย้ายมา
> "หลังบูรณะเสร็จ" · เชื่อมกับ "NPC เดินในเมือง" (ข้อ 12 Roadmap)

## 4. ระบบคลังและกระเป๋า (Storage & Inventory Economy)

> 🚧 **สถานะ: ออกแบบเสร็จ รอ implement** — คุยกับพี่แยมสรุปแล้ว ตัวเลขทุกตัวปรับได้
> ตอน implement จริง จุดที่ยัง "ต้องยืนยัน" ทำเครื่องหมาย ⚠️ ไว้

### 4.1 ทำไมต้องมีระบบนี้

แก้ 2 ปัญหาพร้อมกัน:
1. **เกมยังไม่มี money sink** — เดิมเงินไหลออกทางเดียวคือปลดล็อคด่าน (ดูข้อ 10 สมดุล)
   ระบบคลัง/กระเป๋าทำให้เงินมีที่ใช้ต่อเนื่องตลอดเกม
2. **ผลผลิตเก็บทันทีรวมกองเดียว ไม่มีมิติ** — เพิ่มความรู้สึก "จัดการทรัพยากร"
   และให้เหตุผลกับการเดินกลับมาแต่ละด่าน (กลายเป็น "รอบเก็บของ" ที่มีของรออยู่จริง)

**หลักคิดสำคัญ:** ทุกที่เก็บของ "มีอยู่ตั้งแต่เริ่มเกม" หมด — เงินที่จ่ายคือ
**"ขยาย/อัปเกรด"** ไม่ใช่ "ปลดล็อคการมีอยู่" เพื่อไม่ให้มีช่วงที่เล่นไม่ได้เพราะ
ยังไม่ได้ปลดล็อคของจำเป็น (รักษาความ cozy ไม่มี fail state)

### 4.2 ที่เก็บของ 3 ชั้น — แต่ละอันเก่งคนละเรื่อง

| | 🎒 กระเป๋าผู้เล่น | 🏠 คลังประจำด่าน | 🏰 คลังเมืองหลวง |
|---|---|---|---|
| **บทบาท** | ตัวกลาง "ขนของ" | ต้นทาง — ที่ผลผลิตเกิด | ปลายทาง — ศูนย์รวม |
| **ของมายังไง** | ผู้เล่นเก็บเข้าเอง | ผลผลิตกองสะสมเอง แม้ไม่อยู่ | ผู้เล่นเอามาฝาก (หรือเช่าส่งอัตโนมัติ) |
| **ลิมิต** | นับ "ช่อง" (เริ่ม 12) | นับความจุต่อด่าน | ความจุใหญ่ ขยายได้ |
| **จ่ายเงินเพื่อ** | ซื้อช่องเพิ่ม (ช่างเครื่องหนัง) | ขยายความจุด่านนั้น | ขยายความจุ + เช่าส่งอัตโนมัติ |
| **มีตั้งแต่** | เริ่มเกม | ตอนปลดล็อคด่านนั้น | เริ่มเกม (บ้านผู้เล่น) |

### 4.3 การไหลของของ (Transport Loop)

```
ด่าน (ผลผลิตกองสะสม)  ──เดินไปเก็บ──►  🎒 กระเป๋า (จำกัดช่อง)
                                            │
                                    เดิน/วาร์ปกลับเมืองหลวง
                                            │
                                            ▼
                                   🏰 คลังเมืองหลวง (ฝากของ)
```

- **กระเป๋า = "รถขนของ"** ลิมิตช่องกำหนดว่าขนได้ทีละกี่ชนิด ต่อรอบ
- ✅ **สรุปแล้ว — คราฟ/ปลดล็อค/ส่งเควส ดึงวัตถุดิบจาก "กระเป๋าผู้เล่น" เท่านั้น**
  (ไม่ดึงจากคลังเมืองหลวง) — ของที่จะใช้ต้องถืออยู่ในมือเสมอ ตรงไปตรงมา เข้าใจง่าย
  · **ผลที่ตามมา:** คลังเมืองหลวงกลายเป็น **"ตู้เก็บของส่วนเกิน" (locker)** ล้วนๆ
  ไม่ใช่ทางผ่านบังคับก่อนคราฟ — ผู้เล่นฝากของที่ยังไม่ใช้ไว้ แล้วมาเบิกตอนต้องการ
  · ทำให้ทุก interaction ยังคงกฎ `nearEnough()` เดิม (ต้องเดินไปถึงถึงทำได้)

### 4.4 กระเป๋าผู้เล่น — ระบบช่อง

- นับเป็น **"ช่อง" (สแตก)** ไม่ใช่จำนวนรวม · 1 ช่อง stack ได้ **99 ชิ้น**
- ✅ **v1.11.1:** ของชนิดเดียวกันเกิน 99 ชิ้น **เปิดสแตกใหม่ของชนิดเดิมได้เอง** แทนที่จะโดนตัดทิ้งที่ 99 (เช่น น้ำผึ้ง 99 + เก็บมาอีก 1 → กลายเป็นน้ำผึ้ง 2 ช่อง: 99 กับ 1) กินช่องเพิ่มเหมือนของชนิดใหม่ปกติ — ของ 1 ชนิดจึงถือได้ไม่จำกัด ตราบใดที่ยังมีช่องว่างพอเปิดสแตกใหม่ (คลังเมืองหลวง ข้อ 4.6 ใช้กลไกเดียวกัน)
- **เริ่ม 12 ช่อง → ซื้อเพิ่มทีละ 4 → เพดาน 32 ช่อง** (5 ครั้งอัปเกรด)
- ซื้อที่ **NPC ช่างเครื่องหนัง** (ดูข้อ 4.7)

**ที่มาของเลข 12→32 (วิเคราะห์จากข้อมูลเกมจริง):**
- ตอนไปปลดล็อคด่าน ต้องถือของใน `unlockCost` — สูงสุด **6 ชนิด** (ร้านซุป) ส่วนใหญ่ 5 ชนิด
- worst case ต่อทริป ≈ 6 (unlockCost) + 4 (ผลผลิตติดมือ) = **~10 ช่อง** ตลอดเกม
- เริ่ม **12** = สบายช่วง Wave 1-3 (ปลดล็อคใช้แค่ 2-4 ชนิด) ไม่กวนตอนเรียนรู้เกม
  แต่พอ Wave 4+ (unlockCost แตะ 6 + อยากสะสมของคราฟหลายอย่าง + ถือของทำเควส)
  จะเริ่มตึงเอง = แรงจูงใจซื้อช่อง + พึ่งคลัง **ตึงตอนที่ควรตึง ไม่กวนตอนเล่นปกติ**
- เพดาน **32** = ปลายเกมสบาย แต่ยังไม่ถึงขั้นถือครบทุกชนิด (เกมมี 186 ไอเทม)
  จึงยังต้องใช้คลังอยู่ดี
- ราคาไล่ขึ้น เช่น 500 → 1,200 → 2,500 → 5,000 → 10,000 (money sink โตตามเกม · ปรับได้)

### 4.5 คลังประจำด่าน

- ผลผลิตของด่านนั้น **กองสะสมที่นี่เอง แม้ผู้เล่นไม่อยู่** (idle/farming feel)
- มี **ความจุจำกัด → เต็มแล้วหยุดผลิต** จนกว่าจะมาเก็บ (กันปลูกทิ้งลืม + สร้างเหตุผลให้กลับมา)
- ✅ **ตัวเลขสรุป (ทำแล้ว v1.5.0):** เริ่ม **30 ชิ้น/ด่าน** → ขยาย +30 ต่อขั้น
  ราคา **800 / 2,000 / 4,500** → เพดาน **120 ชิ้น** (3 ขั้น)
- **ที่มาของเลข (คำนวณจากอัตราผลิตจริง):** ด่านผลิตเฉลี่ย 4.3 ชิ้น/วัน (เร็วสุด
  farm_a 9 ชิ้น/วัน · ช้าสุด 2.3) → **cap 30 = เต็มใน 3.3 วัน (เร็วสุด) / 6.9 วัน (เฉลี่ย)**
  ที่ speed 3x ≈ 1–2.5 นาทีจริง = จังหวะกลับมาเก็บที่กำลังดี ไม่ถี่จนกวน ไม่ห่างจนลืม
- อัปเกรดความจุ = **ปลดล็อคครั้งเดียว จ่ายจบ เป็นของเรา** (เหมือนซื้อยุ้งฉาง
  ไม่ใช่เช่า — คลังด่านเป็นโครงสร้างพื้นฐาน ควรรู้สึก "เป็นเจ้าของ")

### 4.6 คลังเมืองหลวง

- **มีตั้งแต่เริ่มเกม** (บ้าน/ฐานผู้เล่นที่เมืองหลวง)
- **บทบาท = ตู้เก็บของส่วนเกิน (locker)** — ฝาก/เบิกของที่ยังไม่ใช้ · **ไม่ใช่แหล่ง
  วัตถุดิบตอนคราฟ** (คราฟดึงจากกระเป๋าเท่านั้น ดูข้อ 4.3)
- ✅ **ตัวเลขสรุป — นับเป็น "ช่อง" เหมือนกระเป๋า** (99 ชิ้น/ช่อง · mental model
  เดียวกัน เข้าใจง่ายกว่านับชิ้น):

| | ช่อง | ราคา |
|---|---|---|
| เริ่มต้น | 40 | — (มีให้ฟรี) |
| ขยายขั้น 1 | 60 | 1,500 |
| ขยายขั้น 2 | 80 | 4,000 |
| ขยายขั้น 3 | 100 | 9,000 |

  > เริ่ม 40 = มากกว่ากระเป๋า (12–32) ชัดเจน แต่ยังไม่ถึง 186 ไอเทมทั้งเกม
  > → ผู้เล่นต้องเลือกว่าจะเก็บอะไร (มีการตัดสินใจ) ไม่ใช่ตู้ไม่จำกัด

- ✅ **ค่าเช่าบริการส่งของอัตโนมัติ:** **500 เหรียญ / 7 วันเกม** (ผลผลิตจากคลังด่าน
  ทุกด่านไหลเข้าคลังกลางเอง ไม่ต้องเดินขน)
  - เปิด/ปิดได้ตามใจ · **ไม่จ่าย = บริการหยุด กลับไปเดินเก็บเองแบบเดิม ไม่มีบทลงโทษอื่น**
  - ราคานี้เบาโดยตั้งใจ (เควสเดียวได้ ~100–200 เหรียญ) — เป็น money sink ต่อเนื่อง
    ที่ไม่สร้างความเครียด ตรงกับหลัก cozy ไม่มี fail state
  - ⚠️ ตอน implement: แจ้งเตือนล่วงหน้าก่อนหักเงิน + ถ้าเงินไม่พอให้หยุดบริการเงียบๆ
    (อย่าติดลบ อย่าเด้ง popup ซ้ำๆ)

### 4.7 NPC ช่างเครื่องหนัง (Bag Craftsman)

- **NPC บริการ ไม่นับเป็น 1 ใน 63 ด่าน** — ไม่อยู่ใน `DEF` array (ถ้าแทรกจะทำให้
  prereq chain ของทั้ง 63 ด่านเลื่อนหมด ผิดกฎใน CLAUDE.md) วางเป็นวัตถุในโลก
  เหมือนจุดวาร์ป
- อยู่ที่ **เมืองหลวง เปิดใช้ตั้งแต่เริ่มเกม** (ต้องซื้อช่องกระเป๋าได้ตั้งแต่ต้น)
- หน้าที่: ขายช่องกระเป๋าเพิ่ม (ข้อ 4.4)
- **ปูทางเนื้อเรื่อง:** เป็น NPC "มีตัวตน" ตัวแรกๆ ที่ไม่ใช่แค่ร้านคราฟ — เชื่อมกับ
  ไอเดีย "ชาวเมืองที่หายไปกลับมา" + "NPC เดินในเมือง" ที่คุยกันไว้ (ดูข้อ 12 Roadmap ด้านล่าง)

### 4.8 ตลาดรับซื้อของ (Market NPC) — ทางระบายกระเป๋าเต็ม + รายรับทางที่ 2

> ปัญหาที่พี่แยมเจอจริงตอนเล่น: **กระเป๋าเต็ม → คราฟไม่ได้** (`doCraft` ต้องมีที่ว่างรับของที่คราฟเสร็จ
> ไม่งั้น rollback วัตถุดิบคืนแล้วยกเลิกทั้งหมด) ตอนนี้มีทางแก้กระเป๋าเต็มแค่ทางเดียวคือฝากเข้าคลังเมืองหลวง
> (ข้อ 4.6) แต่คลังก็เต็มได้เหมือนกัน — ต้องมีทาง "ทิ้งของแลกเงิน" ด้วย ไม่ใช่แค่ "ย้ายที่เก็บ"

**รูปแบบ:** NPC ใหม่ 1 ตัว **"แรคคูนพ่อค้าตลาด"** — ตัวละครฮิวแมนนอยด์แรคคูน คาแรกเตอร์
มาสคอตใหม่ของฝั่งร้านค้า (แยกจากน้องโคโค่ซึ่งเป็น Spirit คู่หูที่เดินตามผู้เล่น ข้อ 5.2 —
คนละบทบาทคนละตัวกันชัดเจนตามที่คุยกันไว้) วัตถุในโลกแบบเดียวกับช่างเครื่องหนัง/คลังเมืองหลวง
(ไม่อยู่ใน `DEF` ไม่ใช่ 1 ใน 63 ด่าน ไม่กระทบ prereq chain) วางที่เมืองหลวงตรง "ตลาด" ที่มีชื่อ
อยู่ในแมพอยู่แล้ว (ข้อ 6.1) **เปิดใช้ตั้งแต่ต้นเกม ไม่มีเวลาปิด** — ต่างจาก 26 ร้าน craft โดยตั้งใจ
เพราะมีไว้แก้ปัญหาฉุกเฉินกระเป๋าเต็ม ถ้าปิดเวลาบางช่วงจะช่วยตอนจำเป็นจริงๆ ไม่ได้

- **ยืนตำแหน่งคงที่ ไม่สุ่มเปลี่ยนที่** — ตามธรรมเนียมเดียวกับช่างเครื่องหนัง/คลังเมืองหลวง
  (`findFreeTile()` วางครั้งเดียวตอน world-gen) เพราะร้านนี้มีไว้เป็น "ทางระบายฉุกเฉิน" ตอน
  กระเป๋าเต็ม ผู้เล่นต้องหาเจอเร็วและแน่นอนทุกครั้ง ถ้าสุ่มตำแหน่งจะกลายเป็นต้องออกตามหา
  ขัดกับจุดประสงค์ของมันเอง
- **แยกจากช่างเครื่องหนังชัดเจน — เป็น NPC คนละตัว คนละจุดยืนในเมืองหลวง** ไม่รวมร้าน
  (ตามที่พี่แยมยืนยัน) ช่างเครื่องหนังขายช่องกระเป๋ายังคงเป็นธุระของเขาคนเดิม แรคคูน
  ดูแลแค่ฝั่งรับซื้อของอย่างเดียว
- ชื่อตัวละครยังไม่ได้ตั้ง — เอกสารนี้เรียกไปก่อนว่า "แรคคูนพ่อค้า" (ยังไม่ตั้งชื่อไทย)

> 💡 **ไอเดียที่คุยกันไว้ (ยังไม่ spec สำหรับ implement — บันทึกไว้ก่อน):**
> แรคคูนพ่อค้ามี**พี่น้องฝาแฝด "แรคคูนลึกลับ"** — แรคคูนพ่อค้าเปิดร้านอยู่ที่ตลาด
> (ตำแหน่งคงที่ตามที่ออกแบบไว้ข้างบน) ส่วนแรคคูนลึกลับแอบซ่อนตัวอยู่ในเมืองหลวง
> **ตำแหน่งสุ่ม** ต้องเดินหาเจอ · บางวันทั้งสองตัวจะ**แอบสลับตัวกัน** (ยังไม่คิดว่าจะมีผล
> ต่อ gameplay ยังไง เช่น ราคาต่างกัน/ของพิเศษ/แค่มุกเรื่องราว) — ไอเดียนี้แยกจากสเปค
> ตลาดรับซื้อของด้านบนที่พร้อม implement แล้ว จุดนี้รอออกแบบเพิ่มก่อนส่งน้องเดฟ ยังไม่ตั้งชื่อ

**ราคารับซื้อ — ต่ำกว่าราคาเควสเสมอ (กันไม่ให้เป็นทางลัดแทนเควส เป็นแค่ทางระบาย):**

| ประเภทของ | ราคา/ชิ้น | เทียบกับเควส |
|---|---|---|
| วัตถุดิบ (ของดิบจากด่าน passive) | 3 เหรียญ | เควสให้ 8–15/ชิ้น |
| ของคราฟ (จาก 26 ร้าน) | 10 เหรียญ | เควสให้ 15–25/ชิ้น |

ใช้การแบ่งดิบ/คราฟชุดเดียวกับที่ `questPool()` ใช้อยู่แล้ว (เช็คว่าไอเทมนั้นอยู่ใน `recipes`
ของร้านไหนไหม) ไม่ต้องสร้าง flag ราคาใหม่ต่อไอเทมทีละชนิด

**UI:**
- โมดัลแบบเดียวกับคลัง — list ของในกระเป๋าทั้งหมด แต่ละแถวมีตัวปรับจำนวน (คู่ขนานกับ
  `collectQtyStep`/`whQty` ที่มีอยู่แล้ว) + ปุ่ม "ขาย" ต่อแถว
- ปุ่มรวม **"💰 ขายทั้งหมด"** — กวาดทุกชนิดทุกจำนวนขายรวดเดียว ได้เงินตามราคาต่อชิ้น × จำนวน
  ออกแบบมาให้เป็นทางแก้ด่วนตอนกระเป๋าเต็มโดยเฉพาะ กดปุ่มเดียวจบ ไม่ต้องเลือกทีละชนิด
- ขายแล้ว **ของหายจากกระเป๋าจริง ไม่เหมือนฝากคลัง** — toast บอกยอดเงินที่ได้ทุกครั้งหลังขาย
  ("💰 ขายได้ 240 เหรียญ") ให้รู้สึกชัดว่าของหายไปแลกอะไรมา ไม่ใช่แค่ตัวเลขเงินขยับเงียบๆ
- `nearEnough()` guard เหมือนของทุกอย่างในเกม

**ทำไมไม่รวมเข้ากับคลังเมืองหลวงเลย:** คลังกลาง (`#whModal`) มี contract ชัดว่า
**"ของไม่หายเด็ดขาด"** (ข้อ 4.6) — ถ้าใส่ปุ่มขายปนเข้าไปในหน้าเดียวกัน เสี่ยงผู้เล่นมือลั่น
กดขายทั้งที่ตั้งใจจะฝาก ของหายจริงจะขัดกับ contract เดิมที่วางไว้ แยกเป็น NPC คนละตัวชัดเจนกว่า
("ฝากคลัง" กับ "ขายของ" เป็นคนละการกระทำ คนละที่ ไม่มีทางกดผิดข้ามกันได้)

### 4.9 สรุป Money Sink + Source ทั้งหมดหลังมีระบบนี้

| ช่องทางใช้เงิน (Sink) | แบบ | โตตามเกม |

| ปลดล็อคด่าน (เดิม) | ครั้งเดียว/ด่าน | ✅ ตาม Wave |

| ขยายคลังด่าน | ครั้งเดียว/ด่าน | ปรับได้ |
| ขยายคลังเมืองหลวง | ครั้งเดียว | ปรับได้ |
| เช่าส่งของอัตโนมัติ | **รายงวด** | ✅ ยั่งยืน |

|---|---|---|

## 5. ระบบบูรณะด่าน (Stage Renovation) + มาสคอตน้องโคโค่

> 🚧 **สถานะ: ออกแบบเสร็จ รอ implement** — เป็นระบบใหญ่ที่เปลี่ยนวิธี "ปลดล็อคด่าน"
> ทั้งหมด แนะนำแตกเป็นเฟสเหมือนระบบคลัง · ตัวเลข/รายละเอียดปรับได้

### 5.1 แนวคิด — เปลี่ยนการปลดล็อคเป็นกิจกรรม cozy

เดิมปลดล็อคด่าน = กดปุ่มจ่ายของ+เงินใน modal จบใน 1 คลิก ไม่มีความรู้สึก
ระบบบูรณะเปลี่ยนให้ทุกด่านที่เปิด กลายเป็น **"โมเมนต์"** ที่ผู้เล่นลงมือฟื้นฟู
ที่รกร้างให้กลับมาสวยด้วยตัวเอง — มู้ดอ้างอิง: Genshin Serenitea Pot (วางเฟอร์),
Stardew/Animal Crossing (จัดฟาร์ม), เกมมือถือ cozy วาดมือ

**ข้อดีที่ได้ฟรี:** `unlockCost` เดิม (ไม้ หิน + เงิน) เปลี่ยนบทบาทจาก "ค่าผ่านทาง"
เป็น **"วัสดุก่อสร้าง/บูรณะ"** — มีเหตุผลในเนื้อเรื่องทันที ไม่ใช่แค่ตัวเลขที่ต้องจ่าย

### 5.2 มาสคอต — น้องโคโค่ (Spirit of Demetria)

ตัวละครนำทางประจำเกม (เจ้าเห็ด/หน่อไม้น้อยในภาพ mood ที่พี่แยมชอบ) — เป็น
"วิญญาณแห่ง Demetria" ที่ชวนผู้เล่นฟื้นฟูดินแดน ผูกกับชื่อโปรเจกต์ (NongCoco) พอดี

หน้าที่:
- **นำทาง** — บอกผู้เล่นว่าทำอะไรต่อ (โดยเฉพาะช่วง tutorial) แทนที่ข้อความ HUD แห้งๆ
- **เขียนไดอารี่** — ทุกครั้งที่บูรณะด่านเสร็จ น้องโคโค่จดบันทึกความทรงจำของที่นั้น
  (สะสมเป็นสมุดไดอารี่ = progression ที่จับต้องได้ + ที่เก็บเนื้อเรื่อง)
- **ฉลอง** — โผล่มาดีใจตอนปลดล็อคด่าน/เฟอร์ใหม่

> 💡 ปูทางเชื่อมกับไอเดีย "ชาวเมืองที่หายไปกลับมา" (ดูข้อ 12 Roadmap) — น้องโคโค่
> เป็นตัวเล่าเรื่องกลางที่ร้อยเรียงการกลับมาของ NPC แต่ละตัว

### 5.3 วงจรบูรณะ 4 ขั้น (แทน modal ปลดล็อคเดิม)

เมื่อผู้เล่นเดินไปด่านที่ยัง "รกร้าง" แล้วกดโต้ตอบ เข้าสู่ลำดับนี้:

| ขั้น | ชื่อ | ทำอะไร | ใช้ทรัพยากร |
|---|---|---|---|
| 1 | 🧹 **ทำความสะอาด** | มินิเกมเก็บกวาดหญ้า/หิน/ของรก | ไม่ใช้ของ (แค่ลงแรง) |
| 2 | 🔨 **รีโนเวท** | ซ่อมโครงสร้าง — **จุดที่ `unlockCost` + เงินถูกใช้** | ไม้/หิน/เงิน (คือ unlockCost เดิม) |
| 3 | 🪑 **วางเฟอร์นิเจอร์** | วางเฟอร์บนกริดอิสระแบบ Serenitea Pot | เฟอร์จากแคตตาล็อก |
| 4 | 📖 **ไดอารี่ + ปลดล็อค** | น้องโคโค่จดไดอารี่ → ด่านเริ่มผลิต + ปลดล็อคเฟอร์ใหม่ | — |

หลังขั้น 4 ด่านเข้าสู่ระบบผลิต/คลังปกติ (ข้อ 4)

### 5.4 เฟอร์นิเจอร์

✅ **สรุปแล้ว — เฟอร์ตกแต่งเป็น cosmetic ล้วน ไม่มีผลต่อ gameplay:**
- **เฟอร์ชุดหลัก (บังคับ)** — เช่น แปลงผัก + รั้ว + ป้ายด่าน · ต้องวางครบขั้น 3
  ถึงจะจบบูรณะ · เป็นตัว "ปลดล็อคด่าน" จริงๆ
- **เฟอร์ตกแต่ง (อิสระ)** — ตู้ กระถาง โคมไฟ ม้านั่ง · วางตามใจ แต่งบ้านตัวเอง
  **ไม่มีโบนัสใดๆ สวยอย่างเดียว** → ผู้เล่นแต่งเพราะอยากแต่ง ไม่ต้องคิดเลข min-max
  (cozy แท้ แบบ Animal Crossing / Serenitea Pot)
- แคตตาล็อกเฟอร์ปลดล็อคเพิ่มเรื่อยๆ ตามด่านที่บูรณะ (แรงจูงใจสะสม)

### 5.5 มินิเกม — เบา ไม่ท้าทาย

หลัก cozy: มินิเกมต้อง "ฟิน" ไม่ใช่ "ยาก" — เก็บกวาด = แตะ/ลากของรกให้หายไปพร้อม
เอฟเฟกต์น่ารัก, รีโนเวท = กดตอกซ่อมเป็นจังหวะ · ไม่มี fail ไม่มีจับเวลากดดัน
(ถ้าทำยากไปจะขัดกับมู้ดผ่อนคลายทั้งเกม)

### 5.6 ด่านบทเรียน = farm_a (เปิดเกมมาบูรณะเลย)

**เปลี่ยนจากเดิม:** farm_a เคยเป็นด่านที่ปลดล็อคแล้วตั้งแต่เริ่มเกม (ผู้เล่นสปอนข้างๆ)
→ ตอนนี้ให้เริ่มเป็น **ฟาร์มรกร้าง** ผู้เล่นเปิดเกมมาเจอน้องโคโค่ที่พาบูรณะ
ฟาร์มแรกด้วยกัน = สอนระบบทั้งหมดไปในตัว (clean→renovate→decorate→diary)

Flow เปิดเกม:
1. ผู้เล่น + น้องโคโค่ปรากฏที่ฟาร์มรกร้าง
2. น้องโคโค่: *"ยินดีต้อนรับสู่ Demetria! ที่นี่เคยงดงาม... มาช่วยกันฟื้นฟูนะ"*
3. พาทำทีละขั้น (ขั้นนี้ให้วัสดุฟรีหรือน้อยมาก เพราะเป็น tutorial)
4. บูรณะเสร็จ → น้องโคโค่เขียนไดอารี่หน้าแรก → farm_a เริ่มผลิต → ปลดล็อค
   แคตตาล็อกเฟอร์ + ชี้ทางไปด่านถัดไป (forest_a)

ด่านต่อๆ ไปใช้วงจรเดียวกัน แต่การนำทางของน้องโคโค่จางลง (ไม่จับมือแล้ว) และ
`unlockCost` กลายเป็นวัสดุบูรณะจริง

### 5.7 ผลกระทบต่อระบบเดิม (สำหรับน้องเดฟ)

- **`unlockCost` ไม่เปลี่ยนโครงสร้างข้อมูล** — แค่เปลี่ยน "ที่ใช้" จาก modal ปลดล็อค
  → ขั้นรีโนเวท (ข้อ 5.3 ขั้น 2) · ตัวเลขใน DEF เท่าเดิม
- **farm_a `unlocked` เปลี่ยน `true → false`** + เพิ่มสถานะพิเศษ "tutorial/รกร้าง"
  (แก้ที่ eco_demo.html source of truth ด้วย แล้ว sync)
- ต้องมีข้อมูลใหม่: แคตตาล็อกเฟอร์นิเจอร์, กริดวางเฟอร์ต่อด่าน, สถานะบูรณะของแต่ละด่าน
  (`renovStep`: cleaned/renovated/decorated/done)
- **แนะนำแตกเฟส:** (5a) โครงวงจร 4 ขั้น + มาสคอต + tutorial farm_a → (5b) ระบบวางเฟอร์
  บนกริด + แคตตาล็อก → (5c) มินิเกมเก็บกวาด/ซ่อม + ไดอารี่ · อย่าทำรวดเดียว

### 5.8 ข้อค้างตัดสินใจ

- ✅ **เฟอร์ตกแต่ง = cosmetic ล้วน** (สรุปแล้ว ดูข้อ 5.4)
- 📌 **interactive demo วางเฟอร์** — พี่แยมสั่งว่า **ทำหลังออกแบบด่านเสร็จ**
  (ตอนนี้มี mockup ภาพนิ่ง `renovation_mockup.html` แล้ว) → ต้องออกแบบ layout
  ด่านจริงก่อน (มีเฟอร์อะไรบ้าง วางยังไง) ค่อยทำ demo ให้ลองฟีล
- ⏳ **ยังไม่ได้ออกแบบ:** แคตตาล็อกเฟอร์นิเจอร์จริง (มีอะไรบ้าง ราคาเท่าไหร่),
  layout ชุดหลักของแต่ละ `cat` (farm/animal/forest/craft), ขนาดกริดวางเฟอร์ต่อด่าน

### 5.9 สมุดบันทึก (Journal) — ศูนย์รวมข้อมูล + ไดอารี่ + แจ้งเตือน

รวมหลายอย่างที่คุยกันไว้เป็น **สมุดเล่มเดียว** ที่ค่อยๆ เต็มขึ้นตามที่ผู้เล่นฟื้นฟูเมือง
= ทั้งบันทึกความทรงจำ (เนื้อเรื่อง) + คู่มืออ้างอิง (ข้อมูลจริง) + ตัวตั้งแจ้งเตือน

**ปลดล็อคทีละหน้า (ต่อ 1 ด่าน):** ด่านที่ยังไม่ปลดล็อค = หน้าเงาดำ/??? · ด่านถัดไป
ที่กำลังจะปลดล็อคโชว์ใบ้นิดหน่อย (ผูกกับเข็มทิศ/เควสหลัก ข้อ 8) · ที่ไกลกว่านั้นเป็นเงา
→ ได้ทั้ง completion goal (เติมสมุดให้เต็ม แบบ Pokédex) + แรงจูงใจสำรวจ

**⚠️ อัปเดต: ทำเป็น 2 เฟส** — สเปคเดิมด้านล่างผูก 2 ช่อง (ไดอารี่น้องโคโค่ + NPC
ผู้ผลิต) ไว้กับระบบบูรณะ (ข้อ 5) และ NPC ผู้ผลิต (ข้อ 3.6) ที่ **ยังไม่ implement ทั้งคู่**
พี่แยมเลือกให้ **ทำเฉพาะส่วนที่มีข้อมูลจริงตอนนี้ก่อน** (เฟส 1) ส่วนอีก 2 ช่องเว้นโครงไว้
เฉยๆ เติมทีหลังได้ทันทีที่ 2 ระบบนั้นพร้อม ไม่ต้องรื้อ schema ใหม่

**เฟส 1 — ทำตอนนี้ (ข้อมูลมีจริงครบ):**
- 🌾 ผลิตอะไร — วัตถุดิบ 3 ชนิด (ด่าน passive) หรือสูตรคราฟ 3 สูตร (ร้าน craft)
- 🕐 เวลาเปิด-ปิด — สำหรับร้าน craft (ดึงจาก `SHOP_HOURS` ข้อ 7.2) · ด่าน passive
  โชว์ "เก็บได้ตลอด 24 ชม." แทน
- 🧭 โซน/ทิศ ที่อยู่บนแมพ — ดึงจาก `ZONE_META` เดิม (ไม่ต้องคำนวณใหม่)
- 🔔 ปุ่มติ๊กแจ้งเตือน (opt-in ต่อด่าน) — **real feature ทำได้เต็มรูปแบบตอนนี้เลย**
  ไม่ติดระบบไหน ปิดเป็น default เตือนเมื่อ: ร้านเปิด (`isOpen()` false→true) /
  **คลังด่านเต็มมีของให้เก็บ** (`storageFull(s)` เพิ่ง true — แก้ปัญหา v1.5.0 ที่คลังเต็ม
  แล้วหยุดผลิตเงียบๆ) / มีเควสใหม่จากร้านที่ติ๊ก (`genQuest()` สร้างเควสที่ `npcId`
  ตรงกับด่านที่ติ๊ก) — ส่งผ่าน toast เดิม
- **ปลดล็อคทีละหน้าตามสถานะจริง:** ใช้ธง `stage.unlocked` เดิมแทนระบบบูรณะที่ยังไม่มี
  (ด่านยังไม่ปลดล็อค = หน้าเงาดำ/??? · ด่านถัดไปที่กำลังจะปลดล็อคใบ้นิดหน่อยตามเข็มทิศเดิม)
- ต้องเซฟ/โหลดด้วย: `journalNotify{}` (map stage id → boolean ที่ติ๊กแจ้งเตือนไว้) — เพิ่ม
  เข้าตาราง 14.6 ตอน implement

**เฟส 2 — เติมทีหลังอัตโนมัติ (รอระบบต้นทาง พร้อมแล้วค่อยเสียบ ไม่ต้อง implement ตอนนี้):**
- 📖 บันทึกของน้องโคโค่ — โผล่มาเองตอนระบบบูรณะ (ข้อ 5) เสร็จ (คือ "ไดอารี่" จากข้อ 5.2
  เป็นเล่มเดียวกัน ไม่แยกระบบ) — ก่อนหน้านั้นช่องนี้ในหน้าสมุดว่าง/ซ่อนไว้เฉยๆ
- 👤 NPC ผู้ผลิตที่อยู่ประจำ — โผล่มาเองตอน NPC ผู้ผลิต (ข้อ 3.6) เสร็จ เช่นเดียวกัน

**เวลาเปิด-ปิดร้าน — 2 ที่ทำงานคู่กัน ไม่ซ้ำซ้อน:** สมุดบันทึก = เปิดดูวางแผน
ล่วงหน้า (ร้านนี้เปิดกี่โมง) · ป้ายบนร้านตอนเดินไปถึง = สถานะตอนนี้ (🟢 เปิด/🔴 ปิด)

> ✅ **สถานะ: เฟส 1 ทำแล้ว (v1.12.0)** — ปุ่ม 📔 สมุดบันทึก ที่แถบล่าง (ข้าง
> กระเป๋า/เควส) · จัดกลุ่มหน้าตามโซน (5 โซน) เพราะมี 63 ด่าน ไม่ใช่ scroll เดียวยาว
> ไม่มีปฏิทินเต็ม (วัน/ฤดู) ตามที่ตกลง จนกว่าจะทำระบบเทศกาล (ดูข้อ 7) · ช่องไดอารี่/NPC
> ผู้ผลิต (เฟส 2) ยังไม่ทำ รอระบบต้นทางตามที่ระบุด้านบน

## 6. World Map — แมพเข็มทิศ 5 โซน

### 6.1 แนวคิด

แมพจัดวางตาม **ทิศ** โดยแต่ละทิศมีเอกลักษณ์ทรัพยากรชัดเจน
ผู้เล่นดูแมพครั้งแรกก็รู้ทันทีว่าทิศไหนมีอะไร

```
                    ❄️ เหนือ
                  หิมะ · น้ำแข็ง
                คริสตัล · ป่าลึก
                        │
    ⛏️ ตก ────────  🏰 เมืองหลวง  ──────── 🌾 ออก
  แร่ · เหล็ก        ร้าน NPC ทั้งหมด      ฟาร์ม · สัตว์
  อัญมณี · ทอง       ตลาด · สถานีรถไฟ      ป่า · ชายหาด
                        │
                    🌋 ใต้
                 ลาวา · ถ่านหิน
                  หิน · กำมะถัน
```

### 6.2 การกระจายด่านตามโซน

| โซน | จำนวนด่าน | เนื้อหา |
|-----|----------|--------|
| 🌾 **ออก (east)** | 25 | ฟาร์มทุกชนิด คอกสัตว์ ป่าทั่วไป ชายหาด หนองน้ำ |
| 🏰 **กลาง (center)** | 19 | ร้าน NPC ทั้งหมด (ทุก craft stage อยู่ที่นี่) |
| ⛏️ **ตก (west)** | 8 | ถ้ำแร่ โรงตีเหล็ก + Wave 11 ทั้งหมด |
| 🌋 **ใต้ (south)** | 8 | จระเข้ กระบองเพชร + Wave 10 ทั้งหมด |
| ❄️ **เหนือ (north)** | 3 | ภูเขาหิมะ ป่าเรืองแสง ป่าเรืองแสงลึก |

> ⚠️ **ปัญหาสมดุลที่รู้อยู่แล้ว:** ทิศเหนือมีแค่ 3 ด่าน ดูโล่งกว่าทิศอื่นมาก
> ถ้าจะขยายต่อ แนะนำออกแบบ **Wave 12 — North** (สัตว์หิมะ, คริสตัลน้ำแข็ง,
> ร้านเครื่องดื่มร้อน, ช่างแกะน้ำแข็ง) ให้สมดุลกับทิศอื่น

### 6.3 หลักการวางแมพ (จาก Emil Chronicle Online)

พี่แยมชอบ world map ของ Emil Chronicle เพราะ **ไม่สมมาตร** —
โซนยื่นออกไม่เท่ากัน มีเกาะแยก มีพื้นที่คั่น ทำให้รู้สึกเหมือนทวีปจริง
ไม่ใช่ template ที่ generate มา

ใน prototype ใช้ **value noise** กวนรัศมีของแต่ละโซนให้ขอบหยัก
แล้วมี **ถนน** เชื่อมเมืองหลวงออกไปทุกทิศ

**ตอนพอร์ตเข้า Unity:** ควรเปลี่ยนเป็นแมพที่ออกแบบด้วยมือ (hand-authored tilemap)
แทน procedural — จะคุมองค์ประกอบภาพได้ดีกว่ามาก แต่ยังยึด layout 5 โซนนี้

### 6.4 จุดวาร์ปข้ามโซน (ทำแล้ว v1.3.0)

## 7. ระบบเวลา กลางวัน–กลางคืน

- 1 วันในเกม = **30 นาทีจริง** (`DAY_MINUTES=30` → `DAY_SECONDS=DAY_MINUTES*60`, ที่ speed 1x)
  ปรับได้ 1x / 3x / 8x + หยุด ✅ **ทำแล้ว (v1.13.0–v1.13.1)**
  · ปรับจาก 60 วินาที (v1.12.0 และก่อนหน้า) — พี่แยมเล่นจริงแล้วพบว่าเร็วเกินไป
  ร้านเปิด 9 ชม. มีแค่ ~22 วิจริงให้ทำอะไร แทบไม่ทัน · ที่ 1800 วิ/วัน ร้านเปิด 9 ชม. = ~11
  นาทีจริง ทำงานทันสบายๆ · **ผลข้างเคียงที่รู้ไว้:** `growDays` (1–4 วัน) รอนานขึ้นตามไปด้วย
  ถ้านับเป็นเวลาจริง (สูงสุด ~2 ชม.จริงที่ 1x) แต่เพราะเป็นระบบ idle ไม่ต้องนั่งรอเฉยๆ
  จึงไม่เป็นปัญหาจริง
  · เทียบเกมแนวเดียวกัน (อ้างอิงตอนคุยกัน): Stardew Valley ~14:20 นาที/วัน, My Time at Portia
  ~15 นาที/วัน, Animal Crossing 1:1 เวลาจริง, Minecraft/Terraria ~20–24 นาที/รอบ — 30 นาที
  ของเราอยู่ในช่วงที่กว้างกว่าค่าเฉลี่ยแนวนี้เล็กน้อย แต่พี่แยมเลือกยืนยันที่ 30 นาทีแล้ว
  (เทสผ่าน ปรับสดได้ผ่าน Dev Tools ถ้าอยากลองค่าอื่นภายหลัง)
  · **ปรับสดได้ระหว่างเล่นผ่าน Dev Tools** (v1.14.0, ดูข้อ 13) — ไม่ต้องแก้โค้ด/รีโหลดหน้าใหม่
  ทุกครั้งที่อยากลองความเร็วอื่น
- `time` เป็นเลข 0–1 ต่อวัน: `0` = เที่ยงคืน, `0.5` = เที่ยงวัน
- ช่วงเวลา: กลางคืน → รุ่งเช้า → เช้า → กลางวัน → บ่าย → พลบค่ำ → กลางคืน
- **ผลต่อภาพ:** ท้องฟ้าไล่สี พื้นมืดลง อาคารที่ปลดล็อคแล้วติดไฟหน้าต่าง
  มีแสงกองอุ่นๆ รอบอาคาร ตัวละครถือโคมส่องทาง มี vignette คลุมจอ
- **ผลต่อ gameplay:** ตอนนี้ยังไม่มี — พืชโตตามจำนวน "วัน" ที่ผ่านไปเท่านั้น

### 7.1 เวลาเปิด-ปิดร้าน (ออกแบบแล้ว รอ implement)

ทำให้วงจรเวลามีความหมายกับ gameplay จริง (เดิมมีผลแค่ภาพ) — แต่ **ทำแบบนุ่ม**
เพราะเกมมีปรับความเร็วเวลา + ไม่มี fail state อยู่แล้ว "ร้านปิด" = แค่เร่งเวลา/กลับมาใหม่
ไม่มีบทลงโทษ · เป็น "จังหวะ" ไม่ใช่ "เดดไลน์"

- **คอนเทนต์ที่เข้าธีมอยู่แล้ว:** 🔭 หอดูดาว (npc_observatory) เปิดกลางคืน · ✨ ป่าเรืองแสง
  (forest_glow/forest_final) เก็บได้เฉพาะมืด · ตลาดเช้า/ตลาดกลางคืน
- **⚠️ การผลิต idle ต้องไม่หยุดตอนกลางคืน** — ให้ NPC เดินกลับบ้านได้ แต่คลังยังผลิตต่อ
  (ไม่งั้นเกมช้าลงน่ารำคาญ)
- **ผู้เล่นรู้เวลาเปิด-ปิดจาก:** ป้ายบนร้าน (🟢 เปิด/🔴 ปิด ตอนนี้) + สมุดบันทึก
  (เปิดดูวางแผนล่วงหน้า · ข้อ 5.9) + เข็มทิศ ("เปิดอีก ~N ชม.") + น้องโคโค่กระซิบ
- **ระดับความลึก** (พี่แยมเลือกได้): เบา = ร้าน craft บางร้าน + คอนเทนต์กลางคืน →
  กลาง = NPC มี routine เดินตามเวลา → ลึก = เทศกาล/ฤดูกาล (ต้องมีปฏิทินเต็ม ทำทีหลัง)

## 8. ระบบนำทาง (Guidance)

ปัญหาที่เจอตอนเทสต์: ผู้เล่นไม่รู้ว่าต้องไปปลดล็อคด่านไหนต่อ

`nextUnlockStage()` (ด่านที่ยังไม่ปลดล็อคตัวแรกสุดในสาย):

| ชั้น | รายละเอียด |
|------|-----------|
| 🎯 **เควสหลักในแผง (Q)** | การ์ดบนสุดของแผงเควส โชว์ด่านล็อคถัดไปตรงๆ พร้อมของ/เงินที่ต้องใช้ (ดูข้อ 3.5) |
| 🧭 **เข็มทิศ HUD** | ลูกศรหมุนชี้ทิศจริง + ชื่อด่าน + ระยะ "N ก้าว" · คลิกดูเงื่อนไขได้ |

## 9. ทิศทางศิลป์ (Art Direction)

**สไตล์ที่ต้องการ:** 2D isometric แนวเกมมือถือเกาหลี kawaii
- เส้นขอบหนา (thick outline) · cel-shading
- โทนสีอบอุ่น earthy · ไม่ใช่ photorealistic · ไม่ใช่ tilt-shift
- อ้างอิง: ภาพประกอบร้านคาเฟ่สัตว์น่ารัก, ชุด asset ตลาดผลไม้แบบ isometric

**สเปคเทคนิค tilemap (สำหรับ Unity):**

| หัวข้อ | ค่า |
|--------|-----|
| ขนาด sprite ต่อ tile | 256 × 192 px |
| Pixels Per Unit (PPU) | 128 |
| Pivot Y | 0.17 |
| รูปทรง | Isometric diamond |
| ระบบ | Unity Tilemap + **Rule Tile** สำหรับ autotile |

**ขนาดกล่องมาตรฐาน (ProBuilder / prop):**

| ของ | X | Y | Z | หมายเหตุ |
|-----|---|---|---|---------|
| กล่องมาตรฐาน | 1 | 1 | 1 | 1 ช่องกริด |
| Prop ย่อย | 0.25 | 0.25 | 0.25 | sub-grid |
| **แผงรั้ว (fence panel)** | **0.1** | **0.5** | **1.0** | บาง–สูง–ยาว · **ไม่ใช่** 0.25×0.5×0.5 |

> ⚠️ **บทเรียนจากงานจริง:** เคยสั่งงาน "แผงรั้ว" แล้วได้ "เสารั้ว" มาแทน
> เวลาสั่งงาน 3D ให้ระบุ **แกน X/Y/Z เป็นตัวเลขชัดเจน** เสมอ อย่าใช้คำบรรยาย
> และถ้าต้องการชิ้นเดียว ให้ย้ำว่า "1 ชิ้น" — เอา 2 ชิ้นมาต่อกันจะเห็นรอยต่อบนหน้า top

**ระบบ warp:**
- ฟาร์มกลางแจ้ง → อยู่บนแมพหลัก ไม่ต้อง warp (กดปุ่มโต้ตอบตรงนั้นเลย)
- ร้านค้า / โรงเลี้ยงสัตว์ในอาคาร / ป่า → warp เข้าแมพย่อย
- ⏳ **ยังไม่ตัดสินใจ:** คอกสัตว์กลางแจ้ง (ม้า, เต่า, จระเข้, บ่อปลา) จะ warp หรือไม่

| **ด่าน / Stage** | หน่วยพื้นที่ 1 จุดบนแมพ ที่ปลดล็อคและใช้งานได้ |
| **Wave** | กลุ่มด่านตามลำดับความยาก (1–11) |
| **Passive stage** | ด่านที่ปลูก/เลี้ยงแล้วรอเก็บเกี่ยว |
| **Craft stage / NPC** | ร้านค้าที่แปรรูปของและออกเควส |
| **Zone / ทิศ** | โซนบนแมพ: center / north / east / south / west |
| **Prereq** | ด่านก่อนหน้าที่ต้องปลดล็อคก่อน |
| **เควสหลัก** | การ์ดในแผงเควสที่โชว์ด่านล็อคถัดไปตรงๆ ไม่ใช่เควสสุ่ม ไม่มีเงินรางวัล |
| **เควสรับจ้าง** | เควสสุ่มขอไอเทมจาก NPC แบบเดิม ได้เงินเป็นรางวัล |
| **คลังประจำด่าน** | ที่เก็บผลผลิตประจำแต่ละด่าน ผลผลิตกองสะสมเอง มีลิมิต เต็มแล้วหยุดผลิต |
| **คลังเมืองหลวง** | ศูนย์รวมของที่เมืองหลวง มีตั้งแต่ต้นเกม ขยายความจุ/เช่าส่งของได้ |
| **กระเป๋า (ช่อง)** | inventory ผู้เล่น นับเป็นช่อง เริ่ม 12 ซื้อเพิ่มถึง 32 · 99 ชิ้น/ช่อง |
| **ช่างเครื่องหนัง** | NPC บริการขายช่องกระเป๋า อยู่เมืองหลวง ไม่นับเป็น 1 ใน 63 ด่าน |
| **แรคคูนพ่อค้า** | NPC บริการรับซื้อของ (ทางระบายกระเป๋าเต็ม) อยู่เมืองหลวงตรง "ตลาด" ตำแหน่งคงที่ — มีพี่น้องฝาแฝด "แรคคูนลึกลับ" (ตำแหน่งสุ่ม แอบสลับตัวกันบางวัน — ไอเดียยังไม่ spec) ยังไม่ตั้งชื่อไทยทั้งคู่ |
| **จุดวาร์ป** | วัตถุในแมพ 5 จุด เดินไปกด E วาร์ปข้ามโซนที่ปลดล็อคแล้ว (v1.3.0) |
| **น้องโคโค่** | มาสคอต/Spirit of Demetria — นำทาง เขียนไดอารี่ ฉลองตอนปลดล็อค |
| **บูรณะด่าน** | วงจร 4 ขั้น (สะอาด→รีโนเวท→วางเฟอร์→ไดอารี่) แทนการปลดล็อคด่านแบบกดจ่าย |
| **NPC ผู้ผลิต** | NPC ที่อยู่ประจำ passive stage เป็นคนผลิตวัตถุดิบ (ผู้เล่นไม่ปลูกเอง) |
| **ผู้ประสานเมือง** | บทบาทผู้เล่น: เก็บของจาก NPC ผู้ผลิต → คราฟเอง → ส่งให้ NPC ผู้บริโภค |
| **สมุดบันทึก** | สมุดที่รวมไดอารี่+ข้อมูลด่าน (ผลิต/เวลาเปิด-ปิด/NPC) ปลดล็อคทีละหน้า + ติ๊กแจ้งเตือนได้ |
| **เฟอร์ชุดหลัก/ตกแต่ง** | เฟอร์บังคับวางให้ครบเพื่อจบบูรณะ / เฟอร์วางอิสระตกแต่งตามใจ |
| **น้องโค่** | AI ผู้ช่วยออกแบบเกม (Cowork) |
| **น้องเดฟ** | AI นักพัฒนา (Claude Code) — ผู้รับช่วงต่อโปรเจกต์นี้ |

## 14. ระบบบันทึกเกม (Save / Load System)

> พี่แยมสั่ง: ปุ่มเซฟมือ + autosave (ติ๊กเปิด/ปิดได้) + หลายสล็อต ตั้งชื่อ/ลบได้
> ⚠️ ยิ่งเลื่อนออกไปนานยิ่งเสี่ยง — ตอนนี้มีคลัง 3 ชั้น + เวลาเปิดปิดร้าน + เควสสะสมแล้ว
> เล่นนานๆ แล้ว refresh ของหายได้เป็นชั่วโมง ควรทำเป็นลำดับถัดไป

### 14.1 ที่เก็บข้อมูล
- ใช้ `localStorage` ของเบราว์เซอร์ — ไฟล์เดียวไม่มี server/backend ให้เซฟ จึงเป็นตัวเลือกเดียวที่ทำได้จริงในตอนนี้
- ⚠️ **ผูกกับเบราว์เซอร์ + เครื่องที่เล่น** — ย้ายไฟล์ไปเปิดเครื่องอื่น/เบราว์เซอร์อื่น เซฟจะไม่ตามไปด้วย
  แก้ด้วยปุ่ม **Export/Import เป็นไฟล์ `.json`** (ดาวน์โหลดเซฟออกมาเป็นไฟล์ ก็อปปี้ไปเครื่องอื่นได้ อัปโหลดกลับเข้าเกมได้) —
  ทำพร้อมกันเลยตั้งแต่รอบนี้ เป็น safety net ไม่ต้องรอเฟสถัดไป

### 14.2 หลายสล็อต — ตั้งชื่อ/ลบได้
เก็บ "ดัชนีเซฟ" (รายชื่อสล็อต) แยกจากตัวข้อมูลเกมแต่ละสล็อต จะได้เปิดหน้าเลือกเซฟเร็วโดยไม่ต้องโหลดข้อมูลทุกสล็อตพร้อมกัน

ต่อสล็อตโชว์:
- ชื่อที่ตั้ง (แก้ได้)
- วันที่ในเกม (Day X) + เงินที่มี — พอกวาดตาแล้วรู้ว่าสล็อตไหนคือรอบไหน
- เวลาจริงที่เซฟล่าสุด

ปุ่มต่อสล็อต: ▶️ เล่นต่อ · ✏️ เปลี่ยนชื่อ · 🗑️ ลบ (มี confirm popup กันลบมือลั่น) · ปุ่มรวม ➕ เซฟใหม่ (ตั้งชื่อตอนสร้าง ไม่บังคับ เว้นว่างไว้ระบบตั้งให้เป็น "เซฟ N")
ไม่จำกัดจำนวนสล็อต (ไฟล์เซฟเกมนี้เล็กมาก ไม่ต้องกังวลเรื่องพื้นที่)

### 14.3 ปุ่มเซฟมือ
- 💾 ปุ่มอยู่บนแถบ HUD หลัก เข้าถึงได้ตลอดเวลาไม่ต้องเปิด panel ก่อน
- กดแล้วบันทึกทับ **สล็อตที่กำลังเล่นอยู่** ทันที + toast "💾 บันทึกแล้ว"
- ถ้ายังไม่เคยผูกกับสล็อตไหนเลย (เพิ่งเริ่มเกมใหม่ยังไม่เคยเซฟ) กดครั้งแรกจะถามชื่อสล็อตก่อน 1 ครั้ง จากนั้นกดซ้ำจะทับสล็อตเดิมตลอด

### 14.4 Autosave — ติ๊กเปิด/ปิดได้
- checkbox "🔄 บันทึกอัตโนมัติ" อยู่ในแผงเซฟ/โหลดเดียวกับปุ่ม 💾 · **ค่าเริ่มต้นเปิด** (ปลอดภัยไว้ก่อนตามคอนเซปต์เกมชิลๆ ไม่อยากให้พี่แยมเผลอของหาย)
- ทริกเกอร์ 2 จุด:
  1. ทุกครั้งที่ขึ้นวันใหม่ในเกม (`onNewDay()`) — จุดเช็คพอยต์ธรรมชาติ ไม่ถี่เกินไป
  2. ทุก 3 นาทีจริง เป็น backup เผื่อเล่นวันเดียวยาวๆ ไม่ข้ามวันสักที
- Autosave ทับสล็อตปัจจุบันเสมอ ไม่สร้างสล็อตใหม่ · ไม่มี toast กวนใจ ใช้ไอคอน 💾 กระพริบเบาๆ มุมจอสัก 1 วิให้รู้ว่าเซฟแล้วพอ

### 14.5 หน้าจอเข้าเกม
- เปิดไฟล์ครั้งแรกที่ยังไม่มีเซฟเลย → เข้าเกมใหม่ทันที สร้างสล็อต "เกมใหม่" อัตโนมัติ ไม่ต้องเลือกอะไรก่อน (กันงงตอนโหลดครั้งแรก)
- เปิดไฟล์ตอนมีเซฟอยู่แล้ว → โชว์หน้าจอเลือกเซฟก่อนเข้าเกม (รายการสล็อตตามข้อ 14.2 + ปุ่ม "🆕 เกมใหม่")
- ระหว่างเล่น กด 💾 เปิดแผงเดิมได้ตลอด สลับสล็อต/ลบ/เปลี่ยนชื่อได้ระหว่างเล่น — ถ้าสลับสล็อตทั้งที่มีความคืบหน้ายังไม่ได้เซฟ เตือนก่อน 1 ครั้ง

### 14.6 ข้อมูลที่บันทึกต่อสล็อต

**ต้องเซฟ:**

| ฟิลด์ | เหตุผล |
|-------|--------|
| `day`, `time` | ตื่นมาต่อวัน/เวลาเดิม ไม่รีเซ็ตเป็นเช้า |
| `money`, `inv`, `bagSlots` | เงิน + ของในกระเป๋า + ขยายกระเป๋าไปกี่ช่อง |
| `stages[].unlocked/planted/daysGrown/storage/storageTier` (ทุกด่าน) | ความคืบหน้าด่าน + คลังด่าน (ฟิลด์อื่นในนั้นมาจาก DEF โหลดใหม่ได้ ไม่ต้องเซฟ) |
| `warehouse`, `warehouseTier` | คลังเมืองหลวง + ขยายไปกี่ขั้น |
| `deliveryOn`, `deliveryPaidUntil`, `deliveryWarned` | บริการส่งของอัตโนมัติ |
| `quests[]` (รวม `pinned`), `qSeq`, `nextQuestIn` | เควสที่ถืออยู่ + ที่พินไว้ + ตัวนับสุ่มเควสถัดไป |
| `player.x`, `player.y` | ตำแหน่งตัวละคร ไม่ต้องเดินจากจุดสปอนใหม่ |
| `unlockedZones` (แปลงเป็น array ก่อนเซฟ เพราะเป็น `Set`) | จุดวาร์ปที่ปลดล็อคแล้ว |
| `zoom`, `showMainQuestHud` | preference เล็กๆ เก็บรวมไปด้วยเลยเพราะ implement ง่าย |
| `journalNotify` (map stage id → boolean, ✅ v1.12.0) | ด่านไหนติ๊กแจ้งเตือนไว้ในสมุดบันทึก (ข้อ 5.9) — plain object ธรรมดา ไม่ต้องแปลงพิเศษเหมือน `unlockedZones` |

**ไม่ต้องเซฟ (คำนวณใหม่ได้ หรือเป็นแค่ UI ชั่วคราว):**
`near*` ทุกตัว, `openPanel/openStage/openWarp/openShop/openWh`, `whQty`/`collectQty`,
`nextId` (คำนวณใหม่จาก `stages` ได้ทันที), `speed`, `paused`, `cam`, `player.dir/anim`,
`journalZone` (แท็บโซนที่เปิดอยู่ในสมุดบันทึก — UI ชั่วคราวเหมือน `openPanel`)

### 14.7 เวอร์ชันเซฟ — กันเซฟเก่าพังตอนเกมอัปเดต
ทุกเซฟติดแท็ก `saveVersion` (เริ่มที่ `1`) ไปด้วยเสมอ เพราะระบบเกมยังเพิ่มเรื่อยๆ (บูรณะ/NPC/สมุดบันทึกที่วางแผนไว้ ข้อ 12 Roadmap)
ถ้าโครงสร้างข้อมูลเปลี่ยนในอนาคต ตัวโหลดเช็ค `saveVersion` แล้วรัน migration function เฉพาะจุดได้
แทนที่จะพังหรือของหายเงียบๆ ตอนโหลดเซฟเก่าเข้าเกมเวอร์ชันใหม่
